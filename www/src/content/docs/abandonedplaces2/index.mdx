*Abandoned Places 2* is the 1993 sequel to
[Abandoned Places](/abandonedplaces/), released by ICE Ltd on the Amiga in
English and German. It uses the same ArtGame kernel directory and packer as the
first game, but it rewrote the engine and moved the renderer's piece geometry
into data. Every piece of wall, gate, stairs and monster art ships with a
`.def` file that gives its size and position in its view slot. This project has
done a recon pass and an export pass on it (2026-11-21). The container,
packer and tileset geometry are solved. The tilesets are exported as atlases,
with palettes that are a stated hypothesis.

This page is a curated summary of the raw notes in
[`docs/abandonedplaces2/`](https://github.com/Shaid/crawl/tree/main/docs/abandonedplaces2).
Where the two disagree, the raw notes win.

> **The container and packer are specified on the
> [Abandoned Places page](/abandonedplaces/#the-artgame-directory-shared-with-ap2-confirmed)**
> ([packer section](/abandonedplaces/#the-artgame-packer-shared-with-ap2-confirmed)).
> This page covers only what AP2 does differently.

> **Pitfall: the colours below are not confirmed.** The plane layout of every
> image is confirmed. Which palette each image uses is a hypothesis, and for
> monsters it is probably wrong (see [Palettes](#palettes-a-hypothesis)).
> Judge the shapes, not the colours.

## `ap2.dir`: confirmed

The record is AP1's 32-byte record, with the group field 0 in every record.
There are 5 sections, separated by a 2-byte `0000`, and the file ends with 4
zero bytes. The file opens directly with section 0's first record, with no
leading separator.
Offsets are byte offsets into `ap2.00k`, and **each of sections 0–3 ends exactly
at the size of its blob**: 4/4, zero deviation, 0 contiguity breaks. Section 4
lists `save_00.dat` and `save_01.dat` (401,408 B each), which live on the save
disk and are not shipped, so the unpacker skips that section.

**Verification: 617/617 shipped records.** All 262 packed records unpack with
checksum 0, input fully consumed and size exact. The other 355 are stored
(including the 0-byte `*_99.bpl` placeholders), and for each one stored =
unpacked. The shared unpacker
([`tools/shared/artgame-kernel.ts`](https://github.com/Shaid/crawl/blob/main/tools/shared/artgame-kernel.ts),
commit `09a59a1`) writes 593 files (5.9 MB) to `build/cache/abandonedplaces2/`. The 24-file gap
to 617 is repeated names: 12 files (`chtin.bpl`, `sp_00`–`sp_07.ani` and the
`obj_99` triplet) appear once on each of disks 1–3 with byte-identical data.

## Tileset triplets: self-describing geometry

Each art file is a triplet. `.def` is N records of 28 bytes (14 big-endian
words). `.ofs` is N `u32` offsets into `.bpl`. N is the same for every set of a
family: `wl` 15, `onwl`/`strd`/`stru`/`swg` 9, `gt` 7, `obj` 11, `mon` 14,
`pit` 16, `swp` 20, `sww` 36, `fl` 2. A record whose x offset is `0xFF..` is
an empty slot, which is why some exported atlases hold fewer frames than N.

| Word | Field | Notes |
|---|---|---|
| 0 | w | pixels |
| 1 | h | |
| 2 | x offset inside the slot frame | `0xFF..` = empty slot |
| 3 | y offset | measured from the top of the frame |
| 4 | slot frame width | `wl`: front walls 140/74/46 by depth, sides 27/34/15/8, in mirrored pairs |
| 5 | slot frame height | 135 = the view height |
| 6 | flags | High byte + 1 = colour planes. **Bit 0 = a mask plane follows** |
| 7 | bytes per row | |
| 8 | words per row | |
| 9–10 | 0 | |
| 11 | plane size | `= bytes/row × h` (e.g. 18 × 115 = 2,070) |
| 12 | 0 | |
| 13 | colour data size | `= planes × plane size` for masked records, `0` for unmasked |

The view is 192×135: each `fl_*` triplet is 2 full-frame 192×135 images. A
masked record stores one extra plane, so the step to the next record is
`(planes + 1) × plane size` (`wl_00` record 0: 5 × 2,070 = 10,350).

**Plane layout: sequential planar, colour planes first (plane 0 = bit 0), the
mask plane last. Confirmed.** Null control: across `wl`/`mon`/`obj`/`gt`/`strd_00`,
about 110,000 pixels lie outside the mask, and **0** of them have a non-zero
colour with mask-last. Treating plane 0 as the mask instead leaks 25–85% of the
pixels per family.

> **Correction (2026-11-21).** The recon reported 1,476/1,520 records passing,
> with 44 failures put down to UI art "presumably with no mask plane". That was
> half right. The failures were the unmasked records, which store
> `colour size = 0` and step `planes × plane size`. The old check mis-flagged
> them. Two more cases close the count. `fl_01`–`fl_07`, `fl_50`, `chrset0/1`
> and `icons` have **no `.ofs`**; their records sit back to back. And `chrset0/1`
> and `icons` carry a **single `.def` record that describes one cell repeated**
> through the whole `.bpl`: 128 glyphs 8×13 (3 planes + mask), 128 glyphs 8×10
> (1 plane), and 168 icons 16×16 (3 planes + mask). With those rules,
> **1,962/1,962** non-empty records pass every check, and every `.bpl` ends
> exactly at its last record. Code:
> [`tools/shared/artgame-tileset.ts`](https://github.com/Shaid/crawl/blob/main/tools/shared/artgame-tileset.ts)
> (`checkGeometry`), with test `tools/shared/__tests__/artgame-tileset.test.ts`.
> The masked flag values are `0x0307`, `0x0407`, `0x0405` and `0x0403`. The
> unmasked ones are `0x0302` (floor), `0x0402` (`plheads`, `menu`, two `dispadd`
> records) and `0x0000` (`chrset1`).

### Exported atlases

`npx tsx tools/abandonedplaces2/amiga/export-tilesets.ts` writes **149 atlases
holding 1,962 frames** to `public/assets/abandonedplaces2/amiga/sprites/`. It
covers every triplet of sets 00–07 and 50–53, plus `chest`, `fire`, `fspells`,
`items`, `icons`, `chrset0/1`, `plheads`, `menu`, `dispadd` and `pleffect`.
Each atlas has a JSON sidecar listing, per frame, its atlas rectangle, its
`slotX/slotY/slotW/slotH` (`.def` words 2–5), its plane count, whether it is
masked, and the palette used. `data/tileset-geometry.json` holds the
per-triplet check: 1,962 checked, 1,962 ok.

## Palettes: a hypothesis

The `.clr` files are 32 Amiga `0RGB` words. The exporter's pairing rule:

- Dungeon-set families (4 planes) use indices 0–15 of their own `set_NN.clr`.
- The upper half of each `set_NN` is black except indices 16–18, so 5-plane
  images take indices 16–31 from `display.clr`, the shared UI half.
- `mon_NN` and `obj_NN` are not tied to a set (`mon` goes up to 17, then 50–53).
  They use `set_NN` when NN is below 8, and `set_00` otherwise.

**This is a hypothesis, and the monster half of it is probably wrong.** The
skeleton above is the evidence. Indices 12–15 of the set palettes form a
lime-to-teal ramp, which gives the walls their lime speckle. That ramp is
probably rewritten per depth or per torch level at run time, as Black Crypt
does with its accent ramp (`COLOR26`–`31`). The fix needs either the colour
code in `main` or in-game screenshots (below).

## Dungeon levels: the grid renders

`dng_NN.dat`, 28 levels:

| Offset | Size | Field | Notes |
|---|---|---|---|
| +0 | 2 | width | `0x20` in 28/28 |
| +2 | 2 | height | `0x20` in 28/28 |
| +4 | 40 | 10 × `u32` block offsets | `offs[0] = 0x2C` and `offs[1] − offs[0] = W·H·8` in 28/28; `offs[9] = file size − 2` in 28/28 |
| +0x2C | 8,192 | cell grid | 32 × 32 cells × **8 bytes**, row-major. **Byte 5 bit 0 = solid wall square.** Bytes 0–4 and the `0x40`/`0x80` bits of byte 5 carry per-cell features (doors, decorations, objects?); not decoded |
| `offs[1]`… | varies | 8 more blocks | Probably object, monster and event lists. The `offs[3]` and `offs[6]` blocks are 2-byte `FFFF` terminators |

`dng_00` renders as a coherent 32×32 maze with a solid border. 11 of the 28
levels have a fully solid border. The other 17 (11–15 and 24–27 among them)
have open edges, which would fit outdoor or edge-connected areas. That reading
is a hypothesis.

## The two walker answers

| Question | Answer | Confidence |
|---|---|---|
| **Wall storage** | **Type-derived**: a cell is solid (byte 5 bit 0) or open, and a face is a wall where the neighbour is solid. The same family as AP1, with a cell 4× larger (8 B vs 2 B) that carries more per-cell state. Converts to per-cell faces on import | Grid **rendered** (28/28 header invariants, coherent maze). The loader in `main` has not been traced |
| **Renderer shape** | **Slot table**: pre-drawn bitmaps per view position, cookie-cut with their own mask. The view is 192×135. Walls come as near/mid/far front faces plus left/right side faces in mirrored pairs | Piece geometry **confirmed** (1,962/1,962). The **destination table** (where each slot frame lands in the view) is not found yet; it should be in `main` |

The cross-project table is in
[`docs/walker-map-format-future-decision.md`](https://github.com/Shaid/crawl/blob/main/docs/walker-map-format-future-decision.md),
in "Addendum (2026-11-21, later)". Its AP2 row still cites the recon's
1,476/1,520 figure; the corrected count is 1,962/1,962.

## How AP2 differs from AP1

- **Identical:** the directory record, the per-disk section separators and the
  packer grammar. One decoder unpacks both games.
- **No identical files:** 0 cross-game sha1 matches over every unpacked file of
  64 B or more.
- **Shared code:** a 32-byte window comparison finds 184 windows shared between
  the AP1 kernel and the `AP2` kernel, 211 between AP1 `code` and AP2 `main`, and
  63 between the AP1 kernel and AP2 `main`. The kernel, I/O, packer and some
  engine routines descend from AP1; the game engine was substantially rewritten.
- **Different asset grammar:** AP2 moved the slot geometry into data (a `.def`
  and `.ofs` beside every `.bpl`). AP1's art files are headerless. The level
  cell grew from 2 bytes to 8, on the same 32×32 grid.
