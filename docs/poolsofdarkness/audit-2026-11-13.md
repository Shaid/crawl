# Pools of Darkness (Amiga): gap audit, 2026-11-13

Report-only audit, 2026-11-13. None of these corrections have been applied yet. It was run by an
independent codebreaker re-derivation (own GLIB parser and method-5 decoder written from the spec,
plus read-only use of the repo decoders) over the four Gold Box Forgotten Realms titles; this page
carries the findings that touch Pools of Darkness. Sibling pages:
`docs/poolofradiance/audit-2026-11-13.md`, `docs/curseoftheazurebonds/audit-2026-11-13.md`,
`docs/secretofthesilverblades/audit-2026-11-13.md`.

## Summary verdict

- Containers, codecs, GEO grid and WALLDEF geometry hold up.
- The 8x8 tile format is wrong; every shipped Pools wall texture (`walldef*-view6.png`, 90) is wrong
  pixels. Pools glyphs are 6-plane, and block 0 is a palette, so the index-to-block alignment is
  n -> n+1.
- The "5 truncated files" status is stale: 24/24 decode.
- Palettes are plentiful in the GLIB data (block 0 of all six 8X8D banks) but untracked.
- Biggest risk: circular visual confirmation of the 1bpp decode.

## Claims wrong or overstated

### 1. WRONG: the 8x8 "1bpp, 8 bytes per tile" format (highest impact)

- **Docs say.** Header-less 1bpp MSB-first tiles, one walldef byte = one tile:
  `goldbox-glib-format.md:336` and section 5.7 (:360-390); code
  `tools/shared/goldbox-walltiles.ts:93` (`decode8x8Tiles`).
- **Audit found.** Each "TILE" sub-block is an 8-byte header + P bitplanes, plane-major, header
  `u16 height=8, u16 x, u16 y, u8 widthBytes=1, u8 flag`. For Pools, 56 B = 6 planes. The grammar fits
  Pools 1536/1536 glyph blocks.
- **Pools alignment.** Block 0 is a palette (see Unverified). Index n maps to glyph block n+1 (seam
  lift 0.40, versus 0.21 for n -> n).
- **Evidence.** Family seam-continuity oracle: Curse corrected 0.584 vs null 0.201 (lift 0.48)
  versus 0.09 lift under the shipped reading; cross-title 31/45 universal-glyph partition match with
  PoR.
- **Consequences.** Section 5.6's correction was never propagated to code; the module doc (~line 66)
  still says the question is open.
- **Fix.** New glyph decoder (6-plane grammar, n -> n+1 alignment), re-render using the seam oracle.
  Pools section 3a-old still says "no PNG render" (stale). Row `goldbox-glyph-format`.

### 2. Stale status: "truncated" files

- **Docs say.** Pools `data-structure.md:37-46` and `:240`: 19/24 OK, 5 truncated.
- **Audit found.** The GLIB section 3 correction and the shipped `container-directory.json` report
  24/24 OK, with `compressedTopLevel` 5; the audit's decoder decompresses the compressed files to
  valid bodies with 0 or 1 bytes left over.

### 3. Stale text

- GEO planes 0/1 headings at `:167` and `:172` still say "remain open, escalated" despite
  corrections underneath.
- Pools `TODO.md` paths-tried rows still say "Pending at time of writing".

### 4. OVERSTATED (family-wide): ECL wallset-binding coverage

GLIB `:681-691` and `:860-869`: "every level that resolves at all resolves ALL 3 slots". The audit
measured PoR (24/29, not 26/29) and Secret (15 of 51 slots are 127) specifically; Pools levels were
not singled out. Count 127/255 as unresolved; row `goldbox-ecl-multiwallset-slotfill`.

### 5. GEO verification numbers do not reproduce (conclusion holds)

The best wrong ordering reaches at most 0.57 on the vertical axis and ties on the horizontal axis.
The documented "best of the other 23 permutations 55.7%" does not reproduce.

## Unverified / open

- **Palettes (untracked, hypothesis).** 104 B blocks (8-byte header + 32 RGB triplets) with
  `height=0`: Pools has them in block 0 of all six 8X8D banks, 49 in PIC, 29 in SPRIT, and others.
  Found but not verified against screenshots. Row `goldbox-glib-palette`.
- **Compressed images.** HEAD, BODY, PIC, SPRIT, BIGPIC blocks have header byte 7 = `0x02`; likely
  individually compressed (`goldbox-glib-compressed-images`).
- No row for SOUNDS (`DIG8`), STRINGS (`TEXT`), `.FON`, `SLBR`/`MXTX` music, ITEMS.DAT (2,048 B,
  different MD5 per GLIB title).
- Not re-checked: the Pools v1.3 opcode table, CFG-walk counts beyond the placeholder analysis, plane
  2 meaning.

3. Wire the palette blocks into output.
4. Count 127/255 as unresolved.
5. Add rows `goldbox-glyph-format`, `goldbox-glib-palette`, `goldbox-ecl-multiwallset-slotfill`,
   `goldbox-glib-compressed-images`.
