# Dungeon Master 1 (Amiga): codebreaker gap audit, 2026-11-13

Report-only audit, 2026-11-13. None of these corrections have been applied yet.
Run by an independent codebreaker re-derivation: all probes were fresh Python written by the auditor
(no project code reused). The audit covered Dungeon Master, Chaos Strikes Back and DM II together;
findings that touch DM1 are repeated here so the page stands alone. Sister pages:
`docs/chaosstrikesback/audit-2026-11-13.md`, `docs/dungeonmaster2/audit-2026-11-13.md`.
All offsets are file-relative. `format.md` below means `docs/dungeonmaster-format.md`.

## Summary verdict

- The DUNGEON.DAT layer is more solid than the docs say: section tiling, grid orientation, map counts
  and the checksum are all confirmed from bytes.
- The graphics-codec "verification" is tautological: the "683/683 IMG1 decode with 0 residue" claim
  cannot fail. A real exact-consumption check gives 682/683, with one non-image and five missed
  full-screen images; the true image count is **687**.
- A palette lead exists in `KAOS.FTL`, but `dm1-palette` says none was found.
- `TITL.DAT` (and the sibling animation files) are not in the DMCSB container; they are tagged-chunk
  streams carrying 16-colour palettes.
- Biggest risk: documented "0 residue" and "98.9%"-style metrics are untestable by construction.

## Claims confirmed

- **DMCSB2 container** (DM1 Graphics.DAT): 749 items, data start 5,996, sum of sizes equals the payload
  exactly (452,112), comp == decomp for 749/749.
- **`0x8104` dungeon decompression:** exact declared size in 6/6 files (DM1 x3, CSB Prison x3), bitstream
  consumed to within the last byte. DM1 dungeon id is 10.
- **Header and section layout:** forward tiling exact (header -> map defs -> per-column cumulative counts
  (sum of width words) -> square-first-thing list -> text -> 16 thing types sized
  {4,6,4,8,16,4,4,4,4,8,4,0,0,0,8,4} -> map data lands exactly on EOF or EOF-2). Holds for DM1 EN/FR/DE.
- **Map grid:** column-major with correct dimensions. The per-column cumulative thing-count table matches
  the thing-bit squares in the column-major grid: DM1 412/412. Null control (row-major): 40/412. This
  confirms orientation, dimensions and the hasObject bit.
- **Map count:** 14. DM1 EN/FR/DE share identical counts and map data size.
- **Checksum:** the trailer is the 16-bit sum of all preceding bytes: DM1 EN 0x2853 exact. DM1 FR/DE have
  no trailer.
- **IMG1 grammar:** exact for the real DM1 images, once classification is fixed (finding 1).

## Claims wrong or overstated

### 1. The DM1 "683/683 IMG1 items decode with 0 residue" claim is circular; one of the 683 is not an image
- **Docs say:** `format.md:111-121`, DM1 `docs/dungeonmaster/amiga/data-structure.md` Graphics.DAT section,
  `dungeonmaster-codec.ts:20-22`. Test: `tools/dungeonmaster/amiga/__tests__/dungeonmaster-amiga.test.ts:26-46`.
- **Audit found:** the test only asserts `pixels.length === w*h`; the output array is allocated at that
  size, so the assertion can never fail. An exact-consumption check gives 682/683 candidates consuming
  exactly, with 0 leftover nibbles.
  - **Item 672** (header reads as "130x11", 132 B) overshoots by 2,436 pixels and leaves 238 nibbles. Its
    first word is size-2, so it is a length-prefixed data item, same as items 671-693.
  - The filter w<=350/h<=220/w*h<=40000 wrongly **excludes 5 real full-screen images**: items 1
    (320x153), 4, 5, 728 and 738 (320x200). All five decode exactly in DM1 (and CSB).
  - True image count: **687**, not 683.
- DMCSB2 attribute words equal the item's first two words in 731/749 items, data items included: a
  header copy, not an image/non-image oracle.
- **Fix:** add a consumed-nibble residue assertion; exclude 672, include the five full screens; correct
  "683/683" to 682 + 5 = 687.

### 2. A palette is sitting in KAOS.FTL, but `dm1-palette` says none was found
- **Docs say:** `format.md:302-312` ("No Amiga ... palette recovered").
- **Audit found:** DM1 `KAOS.FTL` has a run of 16 words at about +0x79A:
  `0666 0888 0620 00CC 0840 0080 00C0 0F00 0FA0 0C86 0FF0 0444 0AAA 000F 0FFF`. The first word reads
  0x0020, which may be a preceding field. A second, variant table starts at +0x7BC (`0000 0666 ...`,
  entries 12/13 differ). From memory, this matches the community-known DM dungeon-view palette (ReDMCSB
  G0021); the auditor did not fetch the source to confirm.
- **Fix:** treat as a hypothesis-grade lead. Re-render the atlas with it and compare against a public
  Amiga screenshot, then point `dm1-palette` at it.

### 3. TITL/ENDA/ANIM/SWSH `.DAT` files are not in the DMCSB container, and they carry palettes
- **Docs say:** DM1 `data-structure.md` Files table says TITL.DAT is "likely IMG1/IMGx, same container";
  the `dm1-titl-dat` row repeats it.
- **Audit found:** every one of these files starts with `AN` + `0140 00C8 0004` (320x200x4) and is a
  tagged-chunk stream. Tags seen: AN, BR, P8, PL, SD, SF, MF, EN, SO. **PL chunks hold 16-colour
  palettes** as (index, r, g, b) nibbles (present in CSB TITL/ENDA and DM2 SWSH/ENDA). The quick chunk
  walk did not fully resolve the length semantics, so it stops early. DM1 file: `TITL.DAT`.
- **Fix:** correct the row; add one shared "FTL AN-chunk animation" item to `dungeonmaster-format.md`
  covering all three titles.

### 4. DUNGEON.DAT field mislabelled; forward-check under-claimed
- **Docs say:** `format.md:227` and the `mapDataOffsetWords` field name: per-map offset is in words.
- **Audit found:** the per-map offset is a **byte** offset. 14/14 DM1 maps equal the cumulative byte
  cursor. `findDungeonDataOffsets` multiplies by 2 (`dungeonmaster-dungeon.ts:335`; the audit gives
  this as `dungeon.ts:335`).
- The code comment says projectile/explosion sizes are "not documented" (`dungeonmaster-dungeon.ts:140-143`,
  `format.md:255-258`). In fact CSB's MINI.DAT (60 projectiles, 50 explosions) tiles exactly at **8 and 4
  bytes**, and the same size table appears as data in DM1 `KAOS.FTL`+5346
  (`04 06 04 08 10 04 04 04 04 08 04 ...`).
- **Fix:** rename the field, add both forward checks, add projectile = 8 / explosion = 4 to `RECORD_SIZE`.

### 5. "Visually coherent maze" is weak evidence (now CONFIRMED by a strong oracle)
- **Docs say:** `format.md:265-274`. **Audit:** the column-count oracle above (DM1 412/412, null control
  40/412) replaces it. Cite that instead.

### 6. The "optional 2-byte checksum" was never identified (now CONFIRMED)
- **Docs say:** `format.md:220-221`. **Audit:** it is the 16-bit byte sum, DM1 EN 0x2853 exact; document
  the algorithm and verify it in the reader.

### 7. Cross-title gaps no TODO row tracks (DM1 aspects)
- DM1/CSB Graphics.DAT non-image items 671-748 (about 60): length-prefixed; several have PCM-like lag-1
  correlation (items 675, 687, 711, r1 0.90-0.96); item 694 starts with "COMPAS...". Contrary to
  `dm1-music-sfx`'s "no sample files evident", sound probably lives here.
- DM1 vs CSB Graphics.DAT: 669/749 items byte-identical, 80 differ (2-5, 11, 26, 42-47, 329-378, 504, 550,
  588-650...). The CSB doc's "largely overlapping" can be quantified.
