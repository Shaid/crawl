Report-only audit, 2026-11-13. None of these corrections have been applied yet. It was run by an
independent codebreaker re-derivation (own Python DAX/DAA, tile, seam and hunk code, plus read-only
use of the repo's tsx decoders) over the five Gold Box Krynn/Savage Frontier titles; this page
carries the findings that touch Treasures of the Savage Frontier. Sibling pages:
`docs/championsofkrynn/audit-2026-11-13.md`, `docs/deathknightsofkrynn/audit-2026-11-13.md`,
`docs/darkqueenofkrynn/audit-2026-11-13.md`,

## Summary verdict

- The `tsf-wilderness-render-technique` row ("blocked, static dead end") is mis-framed: the selector
  trampoline loads combat-map icon banks, not a wilderness view.
- Wilderness geos 51-57 fail the adjacency oracle, so the wilderness GEO is a different encoding that
  no row tracks.
- The wallset override is solid for the 29 dungeon geos.
- Biggest risk: effort spent on a trampoline that is irrelevant to wilderness rendering.

## Claims confirmed

- Wallset override covers every GEO slot in use for 29/29 dungeon geos. The audit did not re-run
  Treasures' ECL.

## Claims wrong or overstated

### 1. MIS-FRAMED: `tsf-wilderness-render-technique` "blocked, static dead end"

- **Docs say.** `treasureofthesavagefrontier/TODO.md:80`; `data-structure.md:152-249`.
- **Audit found.** The selector loads combat-map icon banks:
  - `dungcom.tlb` = 25 blocks x 368 B (8 + 24x3x5, i.e. 24x24 5-plane icons), matching the pushed
    count `0x19` = 25.
  - `wildcom.tlb` = 34 x 368 B.
  - `randcom.tlb` = 6 x 440 B (with mask), pushed as count 6 at base `0x22` = 34, i.e. straight
    after WildCom.
  - Gateway's files are 25/34/6 too; Champions' DUNGCOM/WILDCOM/RANDCOM headers declare 24x24 x
    25/35/6 icons. So the trampoline is irrelevant to wilderness rendering.
- **Route to the real answer.** Statically disassemble overlay #1 around its `"Sky"` string (file
  `0x3A042`; Sky.tlb has 3 blocks of 998/278/2483 B).
- **Fix.** Retitle the row and drop `blocked`.

### 2. OVERSTATED: wilderness GEO encoding

Treasures geos 51-57 fail the adjacency oracle (e.g. 8/25, 24/40). That is consistent with them being
wilderness geos, but no row tracks the wilderness GEO encoding. Add row `tsf-wilderness-geo-encoding`.
(Gateway levels 21-26 show the same symptom; see the Gateway page.)
