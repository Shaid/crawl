# Bard's Tale 2 (Amiga): codebreaker gap audit, 2026-11-13

Report-only audit, 2026-11-13. None of these corrections have been applied yet.
Run by an independent codebreaker re-derivation: the auditor wrote its own Python decoders (an
independent Huffman decoder and a stock Okumura LZHUF) and compared them against the TypeScript port.
The audit covered Bard's Tale 1-3 together; findings that are family-wide are repeated here so this
page stands alone. Sister pages: `docs/bardstale1/audit-2026-11-13.md`,
`docs/bardstale3/audit-2026-11-13.md`.

Data location used: `data/_unexplored_/BardsTale2/`. The slave identity strings check out.

## Summary verdict

- The picture codec is correct: the independent Huffman decoder reproduces the TypeScript port on BT2
  61/61 records.
- Two docs claims about the BT2 `unk` field and the placeholder records are wrong; `bt2-unk-field` can
  be closed.
- BT2 records carry an inline animation payload that `Uncrypt1` ignores (50/61 records), and there is no
  TODO row for it.
- Most other BT2 data files use the same `[u32 size][u32 bitcount][Huffman]` container, so the
  "unknown banks" are one codec away from decoded.
- **No map, wall or door encoding is claimed anywhere in the BT docs**, so there was nothing to audit
  there; it is untracked and is the obvious next pass.

## Claims confirmed

- Game identity from the slave strings.
- BT2 bit-transpose plus 14-byte row XOR picture decode: independent decoder matches 61/61. A
  row-interleaved null control renders as noise, and no palette word is above 0x0FFF.
- BT2 has 61 real pictures in 64 slots.
- Bit-count rule (finding 1) holds 61/61 on `pics`, giving the Huffman tree decoder an independent
  zero-deviation check.

## Claims wrong or overstated

### 1. WRONG: "`unk` field is always `0x167B6`, role unknown"
- **Docs say:** `docs/bardstale-picture-format.md:64,256-257`; codec line 616; TODO row `bt2-unk-field`.
- **Audit found:** `unk` is the exact number of bits in the Huffman stream. BT2 `pics`: stored
  **little-endian**, and equals bit count + 7 on 61/61. `0x167B6` never appears in our data.
- **Fix:** document the field, add it as a decoder sanity check, close `bt2-unk-field`.

### 2. WRONG: BT2 placeholder records
- **Docs say:** `picture-format.md:159-167` and the BT2 extractor header: 10-byte `[sizeDst=1][unk]`
  records with "no Huffman tree or payload at all", byte-identical at all 3 slots.
- **Audit found:** slots 25 and 30 end in `c600`; slot 52 ends in `8280`, so they are not identical.
  Each is a valid 1-byte Huffman record: a single-leaf tree that decodes to 0x8C or 0x05. Its unk value
  (LE) = 16 = 9 bits + 7, the same rule as finding 1. The listed `[u32][u32]` header is also only 8
  bytes, not 10.
- **Fix:** reword the doc and the extractor header.

### 3. UNTRACKED / OVERSTATED: BT2 records hold animation data that is ignored
- **Docs say:** `sizeDst` is "32 (palette) + payload" (`picture-format.md:63`, garbled example). There is
  no BT2 TODO row at all.
- **Audit found:** 50/61 BT2 records have `sizeDst - 32 > 4928`, 210,848 extra bytes in total, which
  `Uncrypt1` ignores. (BT1 shows the same inline overlay; see its page.)
- **Fix:** add a `bt2-animation` row and fix the `sizeDst` text.

### 4. UNTRACKED, high value: every BT2 data file uses the same `[u32 size][u32 bitcount][Huffman]` container
- All BT2 data files decode with the existing codec; the bit-count rule from finding 1 holds with zero
  deviation (little-endian + 7 on BT2 `big_dung`, `title` and `pics`).
- 40/40 single-record files across BT1 and BT2 (BT2 members include `big_dung`, `wpics`, `ic`, `title`,
  `bs.anm`, plus the shared instrument files).
- Directory files: BT2 `levs` (25 x 3,072 B), BT2 `citys` (1 x 2,304 + 6 x 512).
- `wpics` is a single 29,728-byte record, not a directory bank.
- So `bt2-other-banks`, `bt2-audio`, `bt2-anm` and `bt2-wpics` all move from "codec unknown" to
  "interpret the decoded payload".
- `chant`, `drums`, `harp`, `panflu`, `trumpet` and `dung_blank` are identical in BT1 and BT2, so
  `bt1-audio` and `bt2-audio` are one job. The instrument files decode to signed 8-bit PCM.

### 5. OVERSTATED: "no count field; counts must be found by decode-until-failure"
- **Docs say:** `picture-format.md:36-43,127-133`; BT2 TODO paths-tried.
- **Audit found:** the first directory offset divided by 4 gives the slot count directly (BT2: 256/4 =
  64). Records run back to back to EOF with the bit-count rule holding. The "not decisive"
  paths-tried entry is wrong; the directory scan was decisive.

### 6. Contradictions between docs and code
- `picture-format.md:123-125` cites an "Errors and fixes" note in `docs/bardstale1/TODO.md` that does
  not exist.
- The codec header (lines 10-12) names a file `pics2` that is not in the corpus, and cites
  `bardstale1/data-structure.md` for the cmp-identical check, which that doc does not contain.
- Typo "implphausible" at `picture-format.md:43`.
- The extractors are not registered in `tools/shared/game-config.ts`; they run standalone.

### 7. UNVERIFIED: "Kroah's `Files/` are cmp-identical" and gallery cross-check
