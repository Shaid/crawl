# Waxworks (Amiga, AGOS): codebreaker gap audit, 2026-11-13

Report-only audit, 2026-11-13. None of these corrections have been applied yet.
Run by an independent codebreaker re-derivation: an independent Python `simon_decr` (`agoslib.py`) plus
probes `t1.py`-`t10.py`, with ScummVM `engines/agos` and scummvm-tools as the reference (citation only).
The audit covered Elvira 1, Elvira II and Waxworks together; shared findings are repeated here so the page
stands alone. Sister pages: `docs/elvira/audit-2026-11-13.md`, `docs/elvira2/audit-2026-11-13.md`.
`agos-pkd-format.md` means `docs/agos-pkd-format.md`.

All retail files match ScummVM's detection MD5 and size exactly (`detection_tables.h:146,486-491,931-937`).

## Summary verdict

- Partial. The core codecs hold up (all 628 `.pkd` files across the three games decode with the read
  pointer at offset 0 and 0 bits left).
- The Waxworks image count is too low: **4,381 valid entries, not 2,318**, and the "15 zones with empty
  vga2 tables" claim is wrong: those are shared-graphics first-person maze zones.
- 46 zones declare 0 palette banks; 39 were exported anyway with noise colours.
- `gameamiga` (simon_decr-compressed here) is the game database, not the executable.
- The `*tune` and `*.out` TODO rows can close; palette claims are overstated.

## Claims confirmed

- **`simon_decr` decode:** all 628 `.pkd` files decode with complete consumption; the 28 tunes, Waxworks
  `gameamiga` and `icon.pkd` pass the same check.
- **Shared container** across the three titles; **3-digit zone ids** for Waxworks (`res.cpp:936-946`).
- **Image codec:** every compressed plane decodes without overrun; uncompressed images fill their gaps
  (Waxworks: 1,153/1,157; the few misses are junk entries). Column-major wins (0.719 vs 0.603 across 6,111
  compressed images).
- **Palette location and scale:** `BE16(vga1+6)` and `*32`.
- **Visual spot-check:** the Waxworks zone 64 tomb render is coherent.

## Claims wrong or overstated

### 1. The picture count is truncated, and so is every "empty zone" claim (WRONG)
- **Docs say:** 5,745 images (`agos-pkd-format.md:219-221`); the walk stops at the first 0-sized entry
  (`:175-176`, `tools/shared/agos-vga.ts:180-206`); "15 more have empty vga2 tables"
  (`docs/waxworks/amiga/data-structure.md:22-23`).
- **Audit found:** the early stop was copied from the debug-only dumper `dumpVgaBitmaps`
  (`debug.cpp:659-677`). The real `drawImage_init` (`vga.cpp:861-874`) looks up `vga2 + image*8` directly
  and returns on a 0x0 entry.
- **Evidence (Waxworks):** early-stop walk 2,318 -> valid entries in the full table **4,381**; **140**
  zones with pictures. 1,061 0x0 placeholders sit mid-table. Uncompressed images fill the gap exactly
  1,153/1,157. Of the image numbers the scripts draw, 2,067 land on valid entries.
- **Fix:** correct the stop rule to "skip 0x0 entries; the table ends at the lowest data offset"; re-count;
  retract the empty-zone statements.

### 2. About 40 zones were exported with palettes read from header bytes (WRONG)
- **Docs say:** the exporter calls `loadPalette(vga1,0,16)` for every zone
  (`tools/shared/agos-vga-export.ts:164`).
- **Audit found:** word `+2` of `vga1` holds the bank count; it equals `(BE16(+10)-BE16(+6))/32` in 321 of
  321 files. **46 Waxworks zones declare 0 banks**; 39 of them were exported anyway with colours from
  header bytes. Example: `0031.pkd`: palette pointer = header pointer = 12, bytes there `0100989a8a20...`.
  `public/assets/waxworks/amiga/textures/zone041.png` shows first-person corridor views in noise colours.
- **Fix:** no palette means no `palettes/zoneNNN.json`; images stay greyscale or take a palette from the
  zone that loads them. Add a TODO row for the palette source of palette-less zones.

### 3. `gameamiga` is the game database, not the AmigaOS executable (WRONG)
- **Docs say:** `docs/waxworks/amiga/data-structure.md:53`.
- **Audit found:** ScummVM lists `gameamiga` as `GAME_BASEFILE` (`res.cpp:107-145,183-209`). Waxworks
  header: `6df 80 6df 29d`, simon_decr-compressed (43,392 -> 101,522 B). The text block's NUL-terminated
  string count equals the header's string-table count: **669/669**. The actual executable is `runit`.
- **Fix:** fix the doc; add `waxworks-gamepc` (items, rooms, exits, subroutines). `icon.pkd` is
  `GAME_ICONFILE` (simon_decr-compressed); `stripped.txt` is the TEXT index (25-byte entries for Waxworks).

### 4. The `*tune` files are simon_decr-compressed ProTracker modules (rows can close)
- **Docs say:** "un-probed; likely tracker-module" (`agos-pkd-format.md:251-254`); row
  `waxworks-tune-music`.
- **Audit found:** all tunes decompress with full consumption and `M.K.` at offset 1080; size equals
  `1084 + patterns*1024 + sample bytes` in 24 of 28 overall. The other 4 are Waxworks `2tune`/`8tune`/
  `9tune`/`10tune`, whose first module ends at exactly 50,980, 51,156, 47,244 and 42,054: ScummVM's
  `amigaWaxworksOffs` sub-tune offsets (`res_snd.cpp:350-379`).
- **Fix:** mark solved; keep a small extractor task.

### 5. `.out` sound files follow ScummVM's raw layouts (rows can close)
- **Docs say:** "undecoded ... probably-uncompressed" (`agos-pkd-format.md:239-246`); row
  `waxworks-out-sfx`.
- **Audit found:** no compression; signed 8-bit PCM at 8000 Hz default. **Waxworks:** a chain of
  `[LE16 size][u16 ?]` + data. All 59 Waxworks files tile exactly to EOF (59/59).
- **Fix:** mark solved; open a small item for the second u16 (values 5, 7, 8, 9, 10, 16), probably a rate
  code.

### 6. The Waxworks "pure-text/dialogue" zones are shared-graphics (maze) zones (WRONG)
- **Docs say:** `docs/waxworks/amiga/data-structure.md:18-22`.
- **Audit found:** the 15 zones with only a `vga1` file (10, 20, 21, 22, 24, 32, 34, 35, 85, 89, 91, 92,
  93, 95, 96) are exactly the zones where `zoneTable[]` = 3 (`zones.cpp:43-86`). They load `vga2` from zone
  18 (zones below 85) or zone 94 (85 and up). Their scripts draw 1,016 image numbers, and all 1,016 resolve
  to valid entries in `0182.pkd`/`0942.pkd`. Zone 41's atlas (see finding 2) shows first-person corridor
  views.
- **Fix:** correct the doc; add a TODO row `waxworks-maze-zones` (shared 18/94 graphics plus room scripts),
  linked to `docs/walker-map-format-future-decision.md:538-563`. No TODO row tracks that section today.

### 7. The palette claims are overstated; one piece of evidence is not reproducible
- **Docs say:** bank 0 is the only bank that matters (`agos-pkd-format.md:151-154`); evidence
  `setPaletteSlot` (`:126-138`); a 0xF96 colour in Elvira 1 zone 64 (`:140-149`).
- **Audit found:** the main load is `vc22_setPalette` (`vga.cpp:1152-1235`), not mentioned. In
  **Waxworks** the palette slot comes from the existing pixel's high nibble (`gfx.cpp:975-976`). Palette
  nibbles are 0-7 in all but a few banks. Waxworks `0391.pkd` bank 0 has real 4-bit values (e.g. `01a1`,
  `034c`), which `*32` wraps. At nibble 7, `*32` gives 224 and `*17` gives 119.
- **Fix:** remove the 0xF96 paragraph; relabel as "per-zone bank 0, rendered (unverified against
  scripts)"; reopen `waxworks-palette-slots`; flag `0391.pkd`.

### 8. The `*-vga1-scripts` rows are mis-scoped
- `vga1` holds palette banks, then image and animation tables, then VC scripts; object definitions and
  room text are in `gameamiga`. Walking scripts: 3,652 scripts for Waxworks, 0 bad opcodes. Rescope to
  "VC script semantics".

### 9. Decompressor table (doc wrong, code fine)
- `agos-pkd-format.md:63-70`: matches `1,00` and `1,01` have fixed length (2, 3) and no extra bits; `1,10`
  reads its length as 8 bits with 12 offset bits (`extract_agos.cpp:104-136`). Code is correct.
  "Uncompressed" is not rare: 1,157/4,381 in Waxworks.

### 10. Inventory errors
- "298 `.pkd`/`.OUT`" for Waxworks is actually 297 zone `.pkd` plus `icon.pkd` plus 59 `.OUT`. "84 screen
  samples" (`agos-pkd-format.md:222`) is actually 124 on disk.
- `docs/waxworks/amiga/data-structure.md:20` cites a non-existent path, `data/agos-pkd-format.md`.
- The Waxworks TODO's "single biggest undecoded lead across all 3 games" (text/tables) applies equally to
  Elvira II.
- Stale comments in `agos-vga.ts`: line 6 points at `data/_unexplored_/...`.
- `tmp.txt` ("Chip - 449360") is a release-group add-on, not retail data; label its provenance.
