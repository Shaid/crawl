# Death Knights of Krynn (Amiga): gap audit, 2026-11-13
> Applied 2026-11-18: see [audit-2026-11-13-changes.md](audit-2026-11-13-changes.md).


Report-only audit, 2026-11-13. None of these corrections have been applied yet. It was run by an
independent codebreaker re-derivation (own Python DAX/DAA, tile, seam and hunk code, plus read-only
use of the repo's tsx decoders) over the five Gold Box Krynn/Savage Frontier titles; this page
carries the findings that touch Death Knights of Krynn. Sibling pages:
`docs/championsofkrynn/audit-2026-11-13.md`, `docs/darkqueenofkrynn/audit-2026-11-13.md`,
`docs/gatewaytothesavagefrontier/audit-2026-11-13.md`,
`docs/treasureofthesavagefrontier/audit-2026-11-13.md`.

## Summary verdict

- DAX container, `8x8d1.daa` tile structure and the quarters model are solid.
- The wallset-binding "CONFIRMED 16/19" claim is wrong or unsupported: slots 2 and 3 are never bound,
  so the walker shows placeholders for roughly 35% of wall faces. A direct 15-slice model covers
  7,953/7,953 wall faces.
- "BE DAA container used for essentially every Amiga-native resource" is overstated: SPRIT and PIC
  banks use a different directory shape and are untracked.
- Biggest risk: a wrong binding model in the walker, plus a doc/TODO list naming a non-existent level.

## Claims confirmed

| Claim | Evidence the audit used |
|---|---|
| DAX container | 199/199 entries. |
| BE DAA on the files it fits | `8X8D0.DAA` and `8X8D1.DAA` byte-identical; id 201's compressed span is 1341/1341 zero bytes. |
| `8x8d1.daa` | 31/31 entries, five planes; quarters model 28 entries x 64 tiles, seam 0.51-0.71 against a 0.17-0.30 null; walldef 7 x 2340 B. |
| GEO prefixes | Non-constant, with repeated values like `0111` x7 and `ccdd` x4 that look like buffer garbage. |
| Palette upper half | Entries 16-31 identical in every Death Knights file (BACK1, BIGPIC1, COMSPR, CPIC1, WILDCOM, DUNGCOM, `8x8d1` id 202). The 5-plane tiles hold only pixel value 0 or 16-31 (27,089 zeros, 0 hits in 1-15), so plane 5 itself selects the upper half. |

## Claims wrong or overstated

### 1. WRONG/UNSUPPORTED: wallset bindings "CONFIRMED 16/19" and "one wallset group per bank"

- **Docs say.** `deathknightsofkrynn/amiga/data-structure.md:148-161`, and the section 3
  hypothesis "one wallset group per bank".
- **Audit found.**
  - Every resolved level binds only slot1; slots 2 and 3 are the 127 sentinel. Yet the GEO uses
    slot-2 wall types in 19/19 levels and slot-3 types in 13/19, so the walker shows placeholders
    for roughly 35% of wall faces.
  - Better model: one 15-slice walldef supplies all three slots (wall type t -> slice t-1), and
    `LOAD PIECES {W,127,127}` means "don't touch slots 2/3". It covers 7,953/7,953 wall faces in
    resolved levels; the shipped per-bank-group model covers 5,132/7,953. Bank-1 levels use slices
    6-15, which contradicts the per-bank reading.
  - Smaller errors: the doc and TODO say the unresolved geo ids are "16, 65, 80". 16 is not a
    level; the export shows 65, 80, 97. "20/105 degenerate renders = literally all-zero view-cell
    bytes" is overstated: only view 6 is zero (e.g. wall 2, slices 9-14); the slices' other views
    carry data.
- **Fix.** Correct the ids in the doc and TODO; test the direct-slice model in the walker; downgrade
  sections 3 and 5 accordingly. The uniform 127/127 in slots 2/3 is the classic sign of a wrong
  decode configuration.

### 2. WRONG/OVERSTATED: SPRIT and PIC `.DAA` banks are not the BE DAA container

- **Docs say.** `data-structure.md:62-65` names `SPRIT1.DAA` as using `readAmigaDaaDirectory`; the
  container is said to be used for "essentially every Amiga-native resource".
- **Audit found.** Death Knights PIC1/PIC2/SPRIT1 (and Champions SPRIT1/2, pic1/2) parse as 0 OK
  under it. They use a third directory shape: u16 BE header length, then 6-byte entries
  `{id u8, 0 u8, offset u32 BE}`, no sizes. Fits 7/7 files: remainder 0, offsets monotonic, pad
  byte always 0. Block payloads start `00 xx 03 00 58 00 0b fc ...`.
- Monster sprites and location pictures are the largest undecoded asset class; no TODO row covers
  them. `globals.daa` and `pointers.daa` (no directory) are also untracked.
- **Fix.** Add row `dkok-sprit-pic-container`; soften the "essentially every" claim.
