# Might & Magic III (Amiga) — Game Rules

Logic foundation for a browser remake's rules core, derived from the game's own 68000 code: the retail `Might&MagicIII` executable (`data/mm3/amiga/Might&MagicIII`, 272,088 B). No other port and no third-party reference code was used for any rule below (DOS-port notes in `docs/mm3/dosvga/` are used only to cross-check *data tables*, section 3). Written 2026-11-25 (pass 1) and 2026-11-26 (pass 2: sections 10-16; pass 3: 17; pass 4: 18; pass 5: 19).

**Method.** Single real routines run in a Unicorn 68000 core (`tools/mm3/rules_oracle/`, no OS/disk/chipset emulation; UI/animation callees are replaced by logging stubs) on synthetic state. Per call the harness records every byte the routine read before writing (the input footprint), every byte it wrote, the return value and each logged stub call. `tools/mm3/rules.ts` is a TypeScript port written from the disassembly; `tools/mm3/__tests__/rules.test.ts` runs it against a *strict* sparse memory seeded with only that footprint, so a port that reads state the game did not read, writes a different byte, draws the RNG in a different order or returns a different value fails. Every group has a **null control**: a deliberately wrong variant must disagree with the vectors somewhere. Same method as MM2 (`docs/mm2/amiga/game-rules.md`), adapted to MM3's overlay-linked executable.

**Address conventions.**
- `R+0xNNNN` = offset into the root `CODE` hunk (86,512 B; its payload starts at file offset `0x28`). `OVn+0xNNNN` = offset into overlay segment *n* (1..8 = hunks 3..10 = the CODE payloads 1,620 / 6,356 / 7,092 / **85,452** / 12,124 / 6,020 / 22,172 / 11,964 B, in file order). The combat/party-action code lives in **OV4** (the 85 KB segment); the root holds the C library, the stat engine and the monster-attack code. Overlay code has no relocations: it is PC-relative plus `A4`-relative.
- `A4` = DATA base + 0x7FFE (SAS/C small data). `-N(A4)` is a global. The DATA hunk is 25,156 B stored, **62,072 B declared**; the harness loads the declared size (zero tail) and every table/global below is inside the `A4` window.
- Calls such as `JSR -31668(A4)` go through the jump table at the start of DATA. Entries `4EF9 <abs32>` are root functions (target = `F_<hex>` in listings); entries from DATA+0x3C0 are 8-byte overlay stubs `BSR.W ovlmgr ; .w seg<<8|flag ; .w offset` (`OV<seg>_<hex>`). 161 root entries + 164 overlay entries.
- Ints are 16 bit; C arguments are pushed right to left, so the **first** argument is at the lowest stack address; the callee returns D0, the caller pops. Characters are 304-byte (0x130) records at `A4-0xC78`, big-endian words in memory.

**Evidence grades.** **harness** = diffed against the game's real routine in Unicorn with null controls; **code** = read from the disassembly at the stated address, not executed; **hyp** = inference; **open** = not derived.

## 10. The monster's turn (harness) — `R+0xA1DC(monster id)`, 3,000 vectors

Callers: the battle round loop (`R+0x12124`, argument 0) and the encounter-start volley (`R+0xC722`, argument = id from the list `A4+0x1F4E[36]`, `0xFF` = none). Logged callees in the harness: `R+0x9E02` (monster hits character, 5.3), `R+0x971C(2)` (miss cue) and `R+0xD1AE` (redraw).

1. **Who acts.** If `u8 A4-0x33A9 == 0` (a battle turn) the argument is ignored: `k = s8 A4-0x3309 - u8 A4+0x1F74` (actor index minus party size) picks the group whose last member is `u8 A4+0x1F73` / `A4-0x1BA` / `A4-0x1B9` (minus 1) for `k = 0/1/2` (other values read a caller register: not modelled); the slot's status word `A4+0x188E[slot]` must be 0 or 1 (anything else = disabled monster, no action); monster id = `u16 A4+0x173A[slot]`.
2. The attack is repeated `NumA[id]` times (`u8 A4-0x5F04`); each repetition chooses a target by `AttP[id]` (`u8 A4-0x5CE8`; the 90 shipped values: 1 x57, 0 x17, 2 x6, 4 x4, 3 x3, 6 x2, 5 x1):
   - **0** — every party position `0..n-1` in turn, **including incapacitated members**, one attack each.
   - **1** — random by party size `n` (`u8 A4+0x1F74`): `n=1` 0; `n=2..5` `rand(0,n-1)`; `n=6` `rand(1,8)==8 ? 5 : rand(0,4)`; `n=7` `rand(1,10)==10 ? 6 : rand(0,5)`; `n=8` `rand(1,12)==12 ? 7 : rand(0,6)` (the rear-most member is hit about half as often); `n=0` or `>8` leaves position -1.
   - **2..6** — the first position (party order table `u8 A4-0xC81[i]` -> character) whose worst condition is not 0xB..0xF (paralysed, unconscious, dead, stone, eradicated) and whose class (`+0x13`) is 3 / 4 / 8 / 1 respectively, or whose race (`+0x11`) is 2 for `AttP = 6`; if none matches, the random rule above. Class numbers as in 4 (names **hyp**).
3. If the (random) pick is incapacitated (worst condition 0xB..0xF) it is **replaced** by a uniform pick among the others: `list` = order[i] of every capable member, `rand(0, len-1)`, then `order[list[r]]` (**a double lookup through the order table**, as in the code; `r == len` — the `hi+1` overshoot of `rand` — reads the `0xFFFF` filler, i.e. `order[-1]`). If nobody is capable: `u8 A4-0x3307 = 1`, `u8 A4-0x104A = 1` (party wiped / battle over) and the routine returns without the redraw.
4. **Hit chance** (the unit the earlier passes could not find): the attack is an **automatic hit** when `DmgT[id] != 0` (`u8 A4-0x5D42`) or the target's asleep counter `+0x11B != 0`. Otherwise `r = rand(1,20)`: `20` -> a hit is issued, **then** (sic, the code falls through) the normal roll below runs as well; `1` -> miss; else `x = rand(1, HitB) + r + (HitB >> 2)` with `HitB = u8 A4-0x5BDA[id]` and the attack hits iff `x >= AC(target) + k`, `AC = R+0xADE6(char,0)`, `k = level/2 + 15` if `u8 A4+0x1F76[position] != 0` (hyp: the member is defending) else `10`. A hit calls `R+0x9E02(char, position, id)`; a miss plays cue 2. So a natural 20 almost always produces two hit calls.
5. Evidence: 3,000 vectors incl. 555 that end in the wiped-party flags (the flags are pre-cleared, so the write is observable) and 1,131 turns with two or more hit calls; null controls: treating damage-type monsters like the rest, and ignoring AC.

**Absent from this routine** (and not found elsewhere): monster ranged attacks (`Rang`, `u8 A4-0x5C34`, is read only by the monster-position code `R+0x9754`), monster spell casting, flee/morale/summon, call for help. `Spec` is applied inside `R+0x9E02` (5.3) and is also shown by the OV8 Identify-Monster spell (name table `A4-0x45A2`).

### 10.4 Encounter-start volley (code) — `R+0xC5FA`
Shows the encounter picture, then calls `R+0xA1DC(id)` for every non-`0xFF` id in `A4+0x1F4E[0..35]` (each with `A4-0x33A9` as set by the caller), clears `A4-0x33A9/-0x33AA`, and if the mode `A4-0x104A == 5` and every member is in a condition 8..0xF it sets mode 1. This is the monsters' opening attack (surprise-like); how the list and `A4-0x104A == 5` are produced is **open** (`mm3-rules-surprise`).

## 11. Turn order and the round loop

### 11.1 Turn order — `OV4+0x1307C` (harness, 3,000 vectors)
Actors: party positions `0..n-1` (speed = `R+0xD064(char, 4, 0)`, the Speed attribute) then one entry per non-empty monster group (the group's last member's `Spd[id]`, `u8 A4-0x6012`). The order `A4+0x331E[12]` (`0xFF` = unused) lists actor indices by **speed descending, ties by actor index** (party first). When a turn is in progress (`A4-0x3308 != 0xFF`) the actor that held the turn is searched again in the new order and `A4-0x3308` points to its new position (unchanged if the entry at that position is still the same actor; left alone when not found).

### 11.2 Round loop (code) — `R+0x11FA0`
`R+0x12150` = "round over": no actor with a clear flag in `A4+0x3312[12]` remains who can still act (members with worst condition 0xB..0xF never can; monsters always can). The loop: if no monsters or no party -> mode `A4-0x104A = 1`; mark the previous actor done (`A4+0x3312`), advance `A4-0x3308 = (A4-0x3308 + 1) mod (n + groups)`, actor `A4-0x3309 = order[...]`; if the round is over rebuild the order (`OV4+0x1307C`), reset `A4-0x3309/-0x3308 = 0xFF` and clear the flags (new round); a party actor whose worst condition is 8 (asleep) or 0xB..0xF **loses the turn** (same set that blocks casting, 14.1); a capable party actor waits for the player's command (`R+0xC166`); a monster actor (`A4-0x3309 >= n`) runs `R+0xA1DC(0)`, and `A4-0x3307 != 0` ends the battle. Initiative is therefore re-evaluated only when the round is over or a monster dies (12).

## 12. Damage to a monster (harness) — `OV4+0x136E2(char, dmg, mode)`, 3,000 vectors
`mode 0` melee (called with the total of 6.4), `2` fixed, `3` item/thrown, other values = spell kinds (`A4+0x332E`). Target slot `u8 A4-0x3F2B`. In order:
1. `dmg == 0` -> cue 2 and stop. Else a status word of 7 on the target is cleared; cue 1; the animation arrays at `A4+0x715C` (index) are set (`+0x1E8C = 3`; `+0x713C = 2` for mode 2, else `A4-0x3C61[min(kind,6)] + 1`).
2. A monster of id `0x19` hit in melee calls `R+0x122DE(char)` (special reaction, **open**).
3. **Physical resistance**: `mode == 0` or `A4+0x332E == 0`: `p = Phys[id]` (`u8 A4-0x56EE`); `p == 100` -> 0 else `dmg = dmg * (100 - p) / 100` (truncating).
4. **Element**: `e = OV4+0x12D56(mode)` (6.3; **always 0 for spell kinds**, nonzero only for modes 0 and 3) is added; `e > 0` also records the element animation (`+0x1E98`, `+0x710C`).
5. **Spell save** (`mode != 0` only): `OV4+0x82B0(id)` — `rand(1, id+0x32) <= id`, i.e. the **monster id is used as its resistance** — on success the damage becomes 5 (kind 0xB or 0xD), 0x32 (0xF) or `dmg >> 1` (other kinds).
6. `HP` (`u16 A4+0x1492[slot]`): `HP > dmg` -> `HP -= dmg`; otherwise `HP = 0` and the monster **dies**. Damage magnitude cue = `<10 / <50 / <200 / else` (0..3, `OV4+0x12D28`).
7. **Death:** cues 0 and 3; XP `Exp[id]` goes through the party split (6.4); unless `u8 A4-0x1665 == 0x6A` (hyp: a no-reward test mode) `Gold[id]` (u32) is added to `A4+0x70A0` and `Gems[id]` (u16) to the **u32** at `A4+0x709C`; a treasure id `Trea[id] != 0` rolls `rand(1,100)` against `u8 A4-0x3518[Trea-1]` (1, 2, 5, 10, 20, 100 % for treasure ids 1..6) — on success one item is generated (section 13, **harness-verified separately; stubbed here**), `u8 A4+0x709B` (count, max 10) increments and the item bytes (+0x90, +0xA3, +0xB6, +0xC9, +0xDC, +0xEF) are appended to the arrays at `A4+0x70D6 / +0x70CC / +0x70C2 / +0x70B8 / +0x70AE / +0x70A4`. The slot is retired (`u16 A4+0xF42[slot] = A4+0xDEE[slot] = 0x80`, `A4-0x3F2B = 0xFF`), the group-index byte of the animation slot `A4+0x715C` (12 of them: `A4+0x1F73, -0x1BA, -0x1B9, +0x3264, +0x3259, +0x3252, +0x3261, +0x3258, +0x3251, +0x325E, +0x3255, +0x3250`) is cleared and, if the first group is still present, the next target is its last member.
Logged callees: `R+0x971C` cues, `R+0x122DE`, redraw `OV4+0`, the item generator. Null control: no physical resistance scaling.

## 13. Item generator (harness) — `R+0xB83A(grade, buf, slot)`, 3,000 vectors
`grade` 0 -> 1. The slot's seven parallel arrays are cleared (`OV4+0xF08A`). Item id (`+0xDC`): `r1 = d100`, `r2 = d100`: `r1 <= 35`: `r2 <= 30 -> rand(1,6)`, `<= 60 -> rand(7,0x11)`, `<= 85 -> rand(0x12,0x1D)`, else `rand(0x1E,0x21)`; `r1 <= 60`: `r2 <= 70 -> rand(0x22,0x29)` else `0x2A`; else `r2 <= 10 -> rand(0x2B,0x2D)`, `<= 20 -> 0x2E`, `<= 35 -> 0x2F`, `<= 45 -> 0x30`, `<= 55 -> rand(0x31,0x33)`, `<= 65 -> 0x34`, `<= 75 -> rand(0x35,0x39)`, `<= 80 -> rand(0x3A,0x3C)`, else `rand(0x3D,0x45)`.
Enchantments: grade 6 -> one kind `rand(1,4)`; otherwise `n = d100 <= 95 ? 1 : <= 99 ? 2 : 3`; `n = 1`: kind by `d100`: (id >= 0x3D and `<= 90` -> 4), `<= 93 -> 3`, `<= 96 -> 1`, `<= 99 -> 2`, else 4; `n >= 2`: distinct kinds from `rand(1,4)` (re-rolled until different), grade columns `rand(0, grade-1)`. ## 14. Spells

### 14.1 Cast gate (harness)
The caster's chosen spell is `u8 +0x7B` (`0xFF` or `0x4D` = none; 77 spells `0..76`, names in `rules-tables.json`). ### 14.3 Combat spells against monsters (code) — `OV4+0x13282`, mode != 0

- **Build `OV6+0x1A0(class, race, align, sex, stats*, record*)`** (harness, 1,500; null controls: no class skill, no max HP/SP, no race resistances). Class or alignment `0xFF` -> "Select a Class and Alignment before saving.", return 0; empty name (prompt `R+0xB5CE`, 10 chars) -> 0. Else the 0x130 record is zeroed and: name, `+0x124` = u8 `A4-0x1661`, `+0x10` sex, `+0x11` race, `+0x12` alignment, `+0x13` class, attributes `+0x14,16,..,20` (current; the temporary bytes `+0x15..` stay 0), **level `+0x23` = 1**, the six race resistance bytes `+0x111,+0x107,+0x10B,+0x109,+0x10F,+0x10D` from the 5-entry tables `A4-0x260C,-0x2607,-0x2602,-0x25FD,-0x25F8,-0x25F3` (per-race byte tables, indexed 0..4 = Human, Elf, Gnome, Dwarf, H-Orc; the first one is 7/5/20/0/0, the second 7/0/2/5/10), birth year `+0x12A` = year - 18, `+0x25` = u8 `A4-0x1327` (day), spell flags by class (Cleric, Sorcerer, Druid: `+0x7A` = 1 and the four school flags `+0x53..+0x56` = 1, `+0x7B` = 0; Paladin, Archer, Ranger: `+0x53`, `+0x7A` = 1, `+0x7B` = 0; the rest `+0x7B` = 0xFF = no spells), skill flags `+0x27 + A4-0x3AF5[class]` (Robber and Ninja get index 0 = the thievery byte of 18.4; Knight 1, Paladin 5, Sorcerer 4, Druid 6, Ranger 0xB), `+0x27 + A4-0x3AEB[race]` (Human 14, Gnome 16, Dwarf 17), `+0x53 + A4-0x3AE6[class]`, then **starting HP `+0x126` = `R+0xAD56`** and **SP `+0x128` = `R+0xAC46`** (the verified level-1 maxima).
- **Not found:** starting gold, gems or food - the record has no gold field and creation touches no party pool; the new-game initial state is not located (open).

### 19.2 Map event executor `OV4+0xE16E(code0, p0, code1, p1, code2, p2, extra)` (harness, 2,500; null controls: no thievery term, no XP)
Called by the square-action processor `OV4+0x9B86` (`OV4+0xAED6`) with up to three action records. **Lock gate:** object index `A4-0x1044` != 0 and `A4+0x70E2 == 0`; the object's kind (word `A4-0x1046 + 12*i`) 4, 0xC, 0x12, 0x14, 0x17, 0x21, 0x26, 0x28 is a lock (cue 0x14, 0x2A, 0x2A, 0x14, 0x14, 0x2B, 0x14, 0x2B), any other kind skips the gate. A lock bumps `+0x70E2`, sets the object word `A4-0x1048 + 12*i` to 1 and, unless kind 0x14, asks which member picks (`OV4+0xC222`; cancel -> `+0x70E2 = 0xFF`, return 1). `rand(1,4) == 1` springs the trap `OV4+0xED8E(map byte +0x31E, rand(0,6), member)`. The pick succeeds when `thievery(member) + rand(1,20) >= map byte +0x312` (18.4): mode 7, "%s picks the lock!", the member gains **`10 * level * difficulty` XP**. Failure: "%s was unable to pick the lock!", `+0x70E2 = 0xFF`, return 1. **Actions** (code, param): 0x15 append item id (param byte) to the reward list (`+0x709B` count, cap 10; arrays `+0x70A4/AE/B8/C2/CC/D6` = the six item bytes), 0x22 gold += param (u32 `+0x70A0`), 0x23 gems += param (u32 `+0x709C`), 0x42 generate an item of grade `param` with `R+0xB83A` into `A4-0x2F8` and append it, anything else runs the script executor `OV4+0xCB20`; a non-zero result returns 1, and after a 0x43 action a zero result returns 0. **Quirk (kept):** the count byte is re-read before every array write; a count above 0x7F (negative) makes the array writes land in front of the arrays, even on the count itself. **No door bash exists** (19.7).

### 19.3 Shop flows (OV7 item command `OV7+0x3FE2`, venue entries; harness 3,500; null controls: sell flag, broken bit, charge cap)
`c` = character, `slot` = backpack slot, `mode` = price mode (the command's `d7`). Item bytes per slot: `+0x90` (bit 6 cursed/sticky, bit 7 broken, 0x3F charges), `+0xA3`, `+0xB6`, `+0xC9`, `+0xDC` id, `+0xEF`.
- **Sell (`0x4506`)**: id < 0x46 and not bit 6 -> price `OV7+0x3CC(mode, 0x80 | (+0x2F == 0))` (18.2), "Sell %s for %lu gold?", yes -> remove the item, **gold `A4-0x1308` += price**; else "We have no need of this %s!".
- **Repair (`0x45C4`)**: needs bit 7 ("That item is not broken!"); price text `OV7+0x7E0` (sel 0, flags `$C(a5)`), yes and `R+0x8964(0, price, 0)` pays -> bit 7 cleared. **Identify (`0x462A`)**: same with sel 1; paid -> `OV7+0x4E08` builds the "Identify Item" class list.
- **Buy (`0x46EA`)**: into the character `u32 A4+0x3270`; its last slot must be empty (`+0xED`, else "%s's backpack is full."); price mode d7 flags 0; yes and paid -> the six item bytes are copied to the buyer's slot 17, removed from the seller.
- **Discard (`0x4408`)**: refused for the 16 "necessary" ids `A4-0x55CE[16]` and for bit 6; else "Permanently discard %s?" (mode 8 returns 2).

### 19.4 Item-command spells (same unit, harness)
Spell handlers 4, 55, 57, 66 call `OV7+0xF1C(char, mode)`; the mode is the item command's. **Mode 4 Recharge (`0x47F6`)**: ids <= 0x47 with a non-zero `+0xEF` byte gain `rand(1,6)` charges (`+0x90 & 0x3F`, saturating at 0x3F with bits 6/7 kept), cue 0x14; otherwise "Not Rechargeable", cue 0x15. **Mode 5 Duplication (`0x48A8`)**: needs an empty last slot ("Backpack Full"); refuses ("Item too Powerful", cue 0x15) when `+0xC9` is in {9,10,17,18,25,26,33,34,39,40,45,46,50,51,56,57,61,62,71,72}, `+0xA3` in {7,8,14,15,19,20,24,25,32,33,36}, `+0xB6 > 0x11`, `+0xEF > 0x37` or id > 0x48; else the six bytes are copied to slot 17 with the charge bits cleared (`+0x90 & 0xC0`), cue 0x14. **Mode 6 Enchant Item (`0x4A7E`)** (harness, 2,000; null control: no cap): only an item with no enchantment bytes (`+0xA3/B6/C9/EF` all 0) and id <= 0x47 ("Not Enchantable", cue 0x15); the item is regenerated by the real generator `R+0xB83A(grade, record, slot)` with **grade = rand(1, casterLevel/10 + 1) capped at 5** (caster = `u32 A4+0x3270`), the id is restored, cue 0x14. Mode 3 Detect Magic changes no state (display).

### 19.5 Damage to a monster with the real item generator (harness, 3,000; null control: generator skipped)
`OV4+0x136E2` now runs with `R+0xB83A` real: the loot roll, the generator's RNG draws and the six item bytes written to `A4-0x2F8` match the game byte for byte through `rules2.ts` `generateItem` (pass 2 had a fixed-pattern stub).

### 19.6 Encounter-start volley and weapon breaking (harness)
**`R+0xC5FA`** (2,500; null controls: no wipe test, no mode restore, always identity order): picture class = `A4-0x53C8[A4-0x5D42[id]]` of the first listed monster whose class is not 0xC (0xC = the shared picture `u32 A4-0x1676`); the resource is cached in `A4+0xDCA/+0xC22` while `A4+0x21F8` is unchanged; cue `A4-0x53C1[type]`; the redraw loop; party order reset to the identity unless mode 2; one `R+0xA1DC(id)` per listed monster; flags `A4-0x33A9/-0x33AA` cleared; wiped test; mode 5 -> 1 when any member is awake and able (see the correction in 8). **`R+0x122DE(char)`** (1,000): every slot with id < 0x1E and a non-zero equipped byte `+0x7D` gets bit 7 (broken) set - the reaction when the monster id 0x19 is hit.

### 19.7 Search for absent mechanisms, and what stays unexplained
**Method.** A linear scan of all nine code hunks (every word-aligned opcode, independent of control flow, so code reached only through computed jumps and jump tables is included) for any `d16(A4)`, `lea d16(A4)` or `pea d16(A4)` whose displacement falls in the monster slot arrays: ids `A4+0x173A`, status `A4+0x188E`, HP `A4+0x1492`. Any monster behaviour (flee, morale, summon, spell, reinforcement) must read or write these arrays, so the census is closed for direct references (it cannot see an access through a pointer to the array, which the compiler does not emit for these globals). The scan returns 20 hit regions, two of them false positives (OV5 `0xAC` and OV8 `0x2486`: a single hit each, on the displacement word of a `jsr -N(A4)`, not an instruction start), so **18 real regions**: root `R+0x9754` (visible-group builder), `R+0xA1DC` (monster turn), `R+0x11502` (battle start and command dispatch; `R+0x11506` sets mode 2), `R+0x11F42` (an HP-at-maximum test of a monster slot); OV4 `0x3314` and `0x50B2` (**animation timers**: `A4+0x1096[i]` restarts at `rand(0, A4-0x4210[type])`, display only), `0x9B86` (square-action processor; contains an **event action that resets a monster slot** - status 0, timer, HP `A4-0x6120[type]` - at `0xAA9A..0xAB50`), `0x108EC`, `0x11754`, `0x11FF2`, `0x126E2` (**display-list builders** of the monster view), `0x12C38` (party hit), `0x1307C` (initiative), `0x13B36` (**slot creation**: writes the id, `rand(0, A4-0x4210[type])` timer and default type tables `A4-0x3DCE`/`-0x3E9B` for a new monster slot - part of the map loader), `0x13E14` and `0x14AB4` (loader and a slot loop after it); OV5 `0x27C8` (**The Arena**: monsters from `%s.mon` files); OV8 `0xCB0` (spell 24 display). None is a monster flee, morale, summon or spell routine. **Result: absent by this census, still not a proof** - unclassified: the exact opcode of the event monster-reset, the Arena picker, `OV4+0x14AB4`'s loop.
**Spells 24 (Identify Monster, `OV8+0xCB0`) and 37 (Detect Monster, `OV8+0x140A`)** are display screens: they read monster tables/positions and draw through the text/window buffers (`A4-0x1A86`, `A4+0x21FE`); no rules content. **Door bash:** no string "bash"/"knock" in any hunk or `.cc` asset and no second roll beside `OV4+0xE16E`: absent (search result).

## 20. Pass 6 (2026-11-26) - skills, starting state, the absent list from the footprint side

### 20.1 The party skill check `OV4+0x102B6(k)` (jump-table stub `OV4_2B6`; harness, 3,000 vectors, `rules6.py` / `rules6.ts partySkill` / `__tests__/rules6.test.ts`; null controls: all-skills as any, two-skills as any)
The skill bytes are `+0x27+k` of the character record (18 skills, k = 0..17; the Skills screen `OV7+0x3294` lists them and `OV7+0x9E8` counts them: display). **Every skill other than thievery is a *party-level* test**: `partySkill(k)` scans party slots `0..size-1` directly (character index, not the order table), counts members whose byte is non-zero, and answers by the skill's group rule, fixed by a jump table at `OV4+0x10302`:
- **any member** (returns 1 at the first one): 0, 1, 2, 3, 4, 6, 7, 8, 12, 13, 15, 16, 17;
- **two members** (returns 1 when the running count is exactly 2): **9, 10, 11**;
- **every member** (returns 1 when the count equals the party size at that member): **5, 14**;
- `k >= 0x12`: never (the member byte is still read first, as `movea.w` sign-extends `k`).
Callers (code, from the listings): `k = 6` (root `+0x8716`, `+0x9D6A`, `+0x1017E`, `+0x1067E`, `+0x10BC4`) selects the facing indicator in the HUD display list (`0xF + facing`, else the "unknown" icon `0xE`); `k = 0x10` (root `+0x87A4`, only when `A4+0xD3E`) and `k = 0x11` (`+0x87FA`, only when `A4-0x330B`) draw the animated Spot-Secret-Door and Danger-Sense indicators; `k = 4` (root `+0xC940`) gates a display feature (Cartographer, **hyp**: automap); **`k = 0xE`, `9`, `0xB`** (OV4 `+0x789A`, `+0x7946`, `+0x7958`) are the **movement gate** of the party step: the terrain code of the target square (walk test `OV4+0x3DA(x, y)`, jump table at `OV4+0x7966`, 12 terrain codes) lets the party onto the three terrain classes whose branches are guarded by the skill - the Swimmer branch (every member needs it), the Mountaineer branch (two members) and the Path Finder branch (two members); which terrain code is water / mountain / forest-like is **hyp** (names inferred from the skill, not from a string); otherwise the step is refused with cue 9 (`R+0x971C(9)`). The skills 1, 2, 3, 7, 8, 12, 13, 15 and 5 have **no consumer** other than the group count (code; their effect, if any, is through the event engine `OV4+0xCB20`, section 20.3). Thievery (0) keeps its own harnessed roll (18.4).

### 20.2 New-game starting gold / gems / food (code; still **open** as a value)
The three party pools are the globals `u32 A4-0x1308` (gold), `u32 A4-0x1304` (gems), `u16 A4-0x1318` (food); they lie in the **BSS tail** of the DATA hunk (DATA offsets `0x6CF6/0x6CFA/0x6CE6`, beyond the 25,156 stored bytes), i.e. **0 at program start**. A sweep of all nine code hunks for any instruction that writes an immediate or a clear to those displacements finds none (`move.l #imm`, `move.w #imm`, `clr`), and the only writers are: the shops / bank / training payments (harnessed, 15, 19.3), the kill rewards (12), the event stat engine (`OV4+0xD940/0xD948/0xDA30`, 20.3) and the pool edit of OV8 (`OV8+0x5A2/0x5FC`). The save-game and roster files (`MM3-GAMES:save%02d.mm3`, the roster file, `OV3+0x75A` load screen, `OV3+0x1560` save) are read into the global block wholesale, so a *new* party's pools are either 0 or come from a file the retail corpus does not contain (the installer writes `MM3-GAMES:`). **Blocked** on that file; smallest next step: one fresh-game memory snapshot (or the installer's `MM3-GAMES` directory) read at `A4-0x1308/-0x1304/-0x1318`. ### 20.3 The event stat engine `OV4+0xCB20(id, value, id2, value2, who)` (located, not harnessed)
A two-phase routine (about 5.5 KB, up to `OV4+0xE16E`): phase 1 jump table `OV4+0xD02E` (95 ids) takes `value` **away** (HP `+0x128`, the 1-byte stats `+0x22/+0x24/+0x26`, a skill `+0x27+n` / resist `+0x39+n` cleared, gold `+0x12C`, the word `A4-0x131C` ...), phase 2 table `OV4+0xD766` (indexed by `id2`) **gives or sets** `value2` (the same fields; sets use `move.b d4,...` = `+0x10..+0x13`, adds on `+0x126/+0x128/+0x22/+0x24/+0x26`, the pools `A4-0x1308/-0x1304/-0x1318` at `+0xD940/+0xD948/+0xDA30`). It is the effect side of the map-event "trade" opcodes; the lock/reward part is harnessed (19.2). Not ported: ~190 handlers, none with rules beyond the field arithmetic shown.

### 20.4 The absent list, from the footprint side (harness-derived audit, `tools/mm3/rules_oracle/audit_monster_reads.py`)
19.7's census is static and closed for direct references. This audit is the **dynamic complement**: every vector records the exact bytes the real routine read before writing, so the union over a unit's vectors is the set of monster-side state that unit can depend on at all. Over the full sets (about 143,000 vectors):
- the **whole turn pipeline** - the monster's turn `R+0xA1DC` (3,000 vectors over all 90 ids), the round loop `R+0x11FA0` (1,227 reading vectors, 2,500 total), the encounter volley `R+0xC5FA`, the run command, turn order `OV4+0x1307C` and the attack `R+0x9E02` - **never reads a monster's current HP** (`A4+0x1492`: read only by damage-to-monster `mondmg`/`mondmgfull` and spell-vs-monster `spellhit`), so no HP-threshold flee, morale or surrender decision can exist inside it; its monster reads are the id and status words (`A4+0x173A`, `A4+0x188E`) and the tables `Spd`, `AttP`, `NumA`, `HitB`, `DmgN/S/T`, `Spec`;
- **`MonRang` is read by no harnessed routine** (the doc's single position-routine reader `R+0x9754` is not in a unit); **`MonMagi` is a magic *resistance*** (read by `element`, `mondmg*`, `spellhit`), not a monster spell set - so the only monster "spell-like" content is the special-attack type `MonSpec` (the 16 effects of 5.3) and `AttP`/`DmgT`;
- the ranged-attack list `A4+0x1F4E` is read only by the volley;
- a surprise decision would have to read something before the volley's first monster turn; the volley reads the list, `DmgT`, the picture class and the party order only.
Together with the static census (no other code references the slot arrays) this closes the *absent* items for the pipeline as exercised: **monster-side surprise, flee/morale, monster spells and call-for-help are absent from every harnessed path and from every code reference to the slot arrays** (still not a proof for code that reaches the arrays through a computed pointer, which this compiler does not emit for these globals). Door **bash**: unchanged (absent; no string or second roll). Re-run: `python3 tools/mm3/rules_oracle/audit_monster_reads.py`.
