# Elvira II: The Jaws of Cerberus (Amiga, AGOS): codebreaker gap audit, 2026-11-13

Report-only audit, 2026-11-13. None of these corrections have been applied yet.
Run by an independent codebreaker re-derivation: an independent Python `simon_decr` (`agoslib.py`) plus
probes `t1.py`-`t10.py`, with ScummVM `engines/agos` and scummvm-tools as the reference (citation only).
The audit covered Elvira 1, Elvira II and Waxworks together; shared findings are repeated here so the page
stands alone. Sister pages: `docs/elvira/audit-2026-11-13.md`, `docs/waxworks/audit-2026-11-13.md`.
`agos-pkd-format.md` means `docs/agos-pkd-format.md`.

All retail files match ScummVM's detection MD5 and size exactly (`detection_tables.h:146,486-491,931-937`).

## Summary verdict

- Partial. The core codecs hold up (all 628 `.pkd` files across the three games decode with the read
  pointer at offset 0 and 0 bits left).
- The Elvira II image count is too low: **3,273 valid entries, not 2,303**, and the "7 zones empty"
  statement is void.
- 3 zones (including zone 80) were exported with palettes read from bytes that are not palettes.
- `gameamiga` is the game database, not the executable; the room/exit data a walker needs is untracked.
- The `*tune` and `*.out` TODO rows can close; palette claims are overstated.

## Claims confirmed

- **`simon_decr` decode:** all 628 `.pkd` files decode with complete consumption (offset 0, 0 bits left).
  Null control: plain `text*`/`tables*` files fail.
- **Shared container** across the three titles; **2-digit zone ids** for Elvira II (`res.cpp:936-946`).
- **Image codec:** every compressed plane decodes without overrun; uncompressed images fill their gaps
  exactly (Elvira II: 855/856). Column-major wins (0.719 vs 0.603 across 6,111 compressed images; 90.6% vs
  69.3% reach 0.5).
- **Palette location and scale:** `BE16(vga1+6)` and `*32`.
- **Elvira II `Pics/`:** the 4 files are 640x400x4 ILBM, each BODY's ByteRun1 data consumed exactly (e.g.
  26,722/26,722 bytes into 128,000/128,000).

## Claims wrong or overstated

### 1. The picture count is truncated, and so is every "empty zone" claim (WRONG)
- **Docs say:** 5,745 images (`agos-pkd-format.md:219-221`); the walk stops at the first 0-sized entry
  (`:175-176`, `tools/shared/agos-vga.ts:180-206`); "7 zones ... empty" (`docs/elvira2/amiga/data-structure.md:20-21`).
- **Audit found:** the early stop was copied from the debug-only dumper `dumpVgaBitmaps`
  (`debug.cpp:659-677`). The real draw path `drawImage_init` (`vga.cpp:861-874`) looks up `vga2 + image*8`
  directly and returns on a 0x0 entry.
- **Evidence (Elvira II):** early-stop walk 2,303 -> valid entries in the full table **3,273**; zones with
  pictures **100/100**. 198 placeholder 0x0 entries sit mid-table. Uncompressed images fill the gap exactly
  855/856. Of the image numbers the scripts draw, 1,625 land on valid entries.
- **Fix:** correct the stop rule to "skip 0x0 entries; the table ends at the lowest data offset"; re-count;
  retract empty-zone statements. The "Entry 1's offset doubles as the table span" wording fails when entry
  1 is a placeholder.

### 2. Zones exported with palettes read from header bytes (WRONG)
- **Docs say:** each zone's bank-0 palette is at `vga1 + BE16(+6)`; the exporter calls
  `loadPalette(vga1,0,16)` for every zone (`tools/shared/agos-vga-export.ts:164`).
- **Audit found:** word `+2` of `vga1` holds the bank count; it equals `(BE16(+10)-BE16(+6))/32` in 321 of
  321 files. **3 Elvira II zones declare 0 banks** (46 in Waxworks). Elvira II zone 80 was exported anyway,
  with colours taken from header bytes.
- **Fix:** no palette means no `palettes/zoneNNN.json`; images stay greyscale or take a palette from the
  zone that loads them. Add a TODO row for the palette source of palette-less zones.

### 3. `gameamiga` is the game database, not the AmigaOS executable (WRONG)
- **Docs say:** `docs/elvira2/amiga/data-structure.md:80-81`.
- **Audit found:** ScummVM lists `gameamiga` as `GAME_BASEFILE` (`res.cpp:107-145,183-209`). The header
  carries the `0x80` "runtime database" marker (`355 80 ... 45c`). The text block's NUL-terminated string
  count equals the header's string-table count: **1,116/1,116**. The actual executable is `runit`.
- **Fix:** fix the doc; add `elvira2-gamepc` (items, rooms, exits, subroutines via `readItemFromGamePc` /
  `readSubroutineBlock`). `start` is `GAME_RESTFILE`, `icon.dat` is `GAME_ICONFILE`, `stripped.txt` is the
  TEXT index (8-byte entries for Elvira II), `tbllist`/`xtbllist` index `tables*`/`xtable*`.

### 4. The `*tune` files are simon_decr-compressed ProTracker modules (rows can close)
- **Docs say:** "un-probed; likely tracker-module" (`agos-pkd-format.md:251-254`); row `elvira2-tune-music`.
- **Audit found:** all 28 tune files (all games) decompress fully with `M.K.` at offset 1080; size equals
  `1084 + patterns*1024 + sample bytes` in 24 of 28 (the four exceptions are Waxworks).
- **Fix:** mark solved; keep a small extractor task.

### 5. `.out` sound files follow ScummVM's raw layouts (rows can close)
- **Docs say:** "undecoded ... probably-uncompressed" (`agos-pkd-format.md:239-246`); row `elvira2-out-sfx`.
- **Audit found:** no compression; signed 8-bit PCM at 8000 Hz by default. **Elvira II:** 12-byte records
  `[u32 size][u32 id][u32 offset]`. Only one shared `013.OUT` exists, because `loadZone` always loads
  (1,3) (`zones.cpp:96-101`). Tiles to EOF: 1/1.
- **Fix:** mark solved.

### 6. The palette claims are overstated; one piece of evidence is not reproducible
- **Docs say:** bank 0 is the only bank that matters (`agos-pkd-format.md:151-154`); evidence
  `setPaletteSlot` (`:126-138`); a 0xF96 colour in Elvira 1 zone 64 (`:140-149`).
- **Audit found:** the main load is `vc22_setPalette` (`vga.cpp:1152-1235`), not mentioned. In **Elvira II**
  the palette slot comes from the existing pixel's high nibble (`gfx.cpp:975-976`). Palette nibbles are
  0-7 (3-bit) in all but a few Elvira II banks. At nibble 7, `*32` gives 224 and `*17` gives 119.
- **Fix:** remove the 0xF96 paragraph; relabel as "per-zone bank 0, rendered (unverified against
  scripts)"; reopen `elvira2-palette-slots`.

### 7. The `*-vga1-scripts` rows are mis-scoped
- `vga1` holds palette banks, then image and animation tables, then VC scripts; object definitions and
  room text are in `gameamiga`. Walking scripts: 1,368 scripts for Elvira II, 0 bad opcodes. Rescope to
  "VC script semantics".

### 8. Decompressor table (doc wrong, code fine)
- `agos-pkd-format.md:63-70`: matches `1,00` and `1,01` have fixed length (2, 3) and no extra bits; `1,10`
  reads its length as 8 bits with 12 offset bits (`extract_agos.cpp:104-136`). Code (`agos-vga.ts:85-118`)
  is correct. "Uncompressed" is not rare: 856/3,273 in Elvira II.

### 9. Inventory errors
- **Elvira II has text and tables files too:** `text02`-`text09` and `tables01` + `tables03`-`tables09`.
  The doc says only "tables01/03/04" (`docs/elvira2/amiga/data-structure.md:80`) and its TODO row omits
  `text*`. The Waxworks TODO's "single biggest undecoded lead across all 3 games" applies equally to
  Elvira II. Both are plain text with a `stripped.txt` index (cheap).
- File counts: "130 `.pkd`/`.out` files" is actually 130 `.pkd` plus 19 `.out` across the Elvira titles as
  the report states it; "84 screen samples" (`agos-pkd-format.md:222`) is actually 124 on disk.
- Stale comments in `agos-vga.ts`: lines 26-31 cite a non-existent Elvira II "Container format" section.
- `Pics/` provenance: the 4 `Pics/` ILBMs carry a "SKID ROW" credit and are not in ScummVM's file list
  (release-group add-ons, not retail).
