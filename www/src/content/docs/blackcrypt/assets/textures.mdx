# Dungeon Textures

The three dungeon tilesets (`bcdfx`, `bcdfy`, `bcdfz`), shown through real,
208×140 first-person viewport renders produced by **`@seer/dungeon`**, the
same walker package that backs the interactive `tools/walker/` harness. Served
from `/assets/blackcrypt/amiga/textures/`.

Each tileset is shown at its accent ramp, cycling through a handful of real
poses picked from the actual explored maps (hover to pause):

## Reading the tilesets

Each tileset is a bare concatenation of chunks whose directory lives in the
executable, not the file. The 84 named sub-images (47 for `bcdfy`) include side
walls, front walls, ceiling, floor, doors, pits, pillars, alcoves, plaques,
stairs, pull chains, panels, fountains and wall buttons. See
[bcdfx/bcdfy/bcdfz](/blackcrypt/files/bcdfxyz/).

## These are real game output, not illustrations

Earlier versions of this page showed hand-composited mockups: a script picked
plausible-looking dest positions and stacked a fixed "corridor + centrepiece"
layout together by hand, because at the time there was no working renderer to
produce actual game output. That's no longer true. `@seer/dungeon` is now a
verified walker — it reproduces the game's own view-geometry walk
(`buildViewList`), draw order (`compositeDrawList`/`paintOrder`) and indexed
palette compositing byte-for-byte, and every image above is that exact
pipeline run headlessly (`www/scripts/render_dungeon_views.ts`) against a real
`(map, x, y, facing)` pose from the actual exported dungeon data — the same
inputs `tools/walker/` renders interactively in a browser. There is no
separate "illustration" step anymore: this page's build now fails if the real
renderer fails.

Every pose below is reproducible: run the interactive harness
(`npm run dev` at the repo root, then open `tools/walker/index.html` with
these query params) and it renders the identical frame pixel-for-pixel.
