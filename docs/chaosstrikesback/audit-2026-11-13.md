# Chaos Strikes Back (Amiga): codebreaker gap audit, 2026-11-13

Report-only audit, 2026-11-13. None of these corrections have been applied yet.
Run by an independent codebreaker re-derivation: all probes were fresh Python written by the auditor
(no project code reused). The audit covered Dungeon Master, Chaos Strikes Back and DM II together;
findings that touch CSB are repeated here so the page stands alone. Sister pages:
`docs/dungeonmaster/audit-2026-11-13.md`, `docs/dungeonmaster2/audit-2026-11-13.md`.
All offsets are file-relative. `format.md` means `docs/dungeonmaster-format.md`.

## Summary verdict

- The DUNGEON.DAT layer is more solid than the docs say (tiling, orientation, checksum, MINI.DAT
  location all confirmed from bytes).
- The "683/683 IMG1 decode with 0 residue" claim is circular. A real exact-consumption check gives
  682/683, with one non-image and five missed full-screen images; true count **687**. The CSB "23 -> 683
  clean" ADF-fix statement rests on the same tautology (the fix itself is still real).
- A palette lead sits in CSB `disk1/KAOS.FTL`, but `csb-palette` says none was found.
- TITL/ENDA/ANIM `.DAT` files are tagged-chunk streams carrying 16-colour palettes, not DMCSB
  containers.
- Several CSB disk files (`DungeonF/G.DAT`, `HCSB.DAT` ...) have no doc or TODO row.

## Claims confirmed

- **DMCSB2 container** (CSB Graphics.DAT): 749 items, Σsize equals the payload exactly (429,401), comp ==
  decomp for 749/749. The ADF-fix container "tiles exactly and 682 items consume exactly".
- **`0x8104` dungeon decompression:** exact declared size in 6/6 files (including CSB Prison x3), dungeon
  id 12.
- **Header and section layout:** forward tiling exact for CSB Prison EN/FR/DE and for CSB MINI.DAT.
- **Map grid:** column-major, per the column-count oracle: CSB Prison 41/41, MINI 296/296 (null control
  row-major: 7/41 and 26/296).
- **Map counts:** 2 (Prison) and 11 (MINI).
- **Checksum:** 16-bit byte sum: CSB Prison 0x939F, MINI 0x7CC6, exact. CSB FR/DE have no trailer.
- **CSB MINI.DAT** dungeon at offset 10098, unique, ending at EOF (42,786) with a valid checksum.
- **IMG1 grammar:** exact for the real images once classification is fixed.

## Claims wrong or overstated

### 1. The CSB "683/683 IMG1 items decode with 0 residue" claim is circular; one of the 683 is not an image
- **Docs say:** `format.md:111-121`, CSB `data-structure.md` Graphics.DAT section,
  `dungeonmaster-codec.ts:20-22`. Test:
  `tools/chaosstrikesback/amiga/__tests__/chaosstrikesback-amiga.test.ts:31-50`.
- **Audit found:** the test only asserts `pixels.length === w*h`, which cannot fail. Exact-consumption
  check: 682/683 consume exactly (0 leftover nibbles).
  - **Item 672** (header "130x11", 132 B) overshoots by 2,436 pixels and leaves 238 nibbles; its first
    word is size-2, so it is a length-prefixed data item (like 671-693).
  - The w<=350/h<=220/w*h<=40000 filter excludes 5 real full-screen images: items 1 (320x153), 4, 5, 728
    and 738 (320x200). All five decode exactly in CSB.
  - True image count **687**, not 683.
- DMCSB2 attribute words equal the item's first two words in 731/749 items, so they are a header copy,
  not an image/non-image oracle.
- **CSB ADF-fix statement "23 -> 683 clean"** (CSB `data-structure.md`, ADF bug section) rests on the
  same tautology. The fix is still real: the container tiles exactly and 682 items consume exactly.
- **Fix:** add a consumed-nibble residue assertion; exclude 672, include the five full screens; correct
  to 682 + 5 = 687.

### 2. A palette is sitting in KAOS.FTL, but `csb-palette` says none was found
- **Docs say:** `format.md:302-312` ("No Amiga ... palette recovered").
- **Audit found:** CSB `disk1/KAOS.FTL` has the same tables as DM1 at +0x100A: a run of 16 words
  (`0666 0888 0620 00CC 0840 0080 00C0 0F00 0FA0 0C86 0FF0 0444 0AAA 000F 0FFF`, first word 0x0020 may be
  a preceding field) and a variant table (`0000 0666 ...`, entries 12/13 differ). From memory this matches
  the community-known DM dungeon-view palette (ReDMCSB G0021); the source was not fetched to confirm.
- **Fix:** hypothesis-grade lead; re-render the atlas and compare against a public Amiga screenshot, then
  point `csb-palette` at it.

### 3. TITL/ENDA/ANIM `.DAT` files are not in the DMCSB container, and carry palettes
- **Audit found:** each starts with `AN` + `0140 00C8 0004` (320x200x4) and is a tagged-chunk stream
  (tags AN, BR, P8, PL, SD, SF, MF, EN, SO). **PL chunks hold 16-colour palettes** as (index, r, g, b)
  nibbles, present in CSB TITL/ENDA. Length semantics not fully resolved (the quick walk stops early).
  CSB files: `TITL.DAT` (identical on disk1 and disk2), `ENDA.DAT`, `ANIM.DAT`.
- **Fix:** add one shared "FTL AN-chunk animation" item to `dungeonmaster-format.md`.

### 4. DUNGEON.DAT field mislabelled; forward-check under-claimed
- **Docs say:** `format.md:227`, field `mapDataOffsetWords`: per-map offset in words.
- **Audit found:** it is a **byte** offset. CSB: 2/2 (Prison) and 11/11 (MINI) maps equal the cumulative
  byte cursor. `findDungeonDataOffsets` multiplies by 2 (`dungeon.ts:335`).
- Projectile/explosion sizes are called "not documented" (`dungeonmaster-dungeon.ts:140-143`,
  `format.md:255-258`). MINI.DAT has 60 projectiles and 50 explosions and tiles exactly at **8 and 4
  bytes**; the same size table appears as data in CSB `KAOS.FTL`+5448.
- **Fix:** rename the field, add both forward checks, add projectile = 8 / explosion = 4 to `RECORD_SIZE`.

### 5. "Visually coherent maze" is weak evidence (now CONFIRMED)
- `format.md:265-274`. Replace with the column-count oracle (CSB Prison 41/41, MINI 296/296).

### 6. The "optional 2-byte checksum" was never identified (now CONFIRMED)
- `format.md:220-221`. It is the 16-bit byte sum (0x939F Prison, 0x7CC6 MINI). Document and verify it
  in the reader.

### 7. The CSB MINI.DAT location scan is circular, though the answer is right
- **Docs say:** `format.md:284-300`, `dungeon.ts:316`.
- **Audit found:** the seed whitelist `{99,8,13,0,5,6}` includes 13, the answer's own seed, so the
  "independent manual scan" is not independent. A seed-agnostic scan (exact forward tiling + byte-sum
  checksum) finds a **unique** hit at 10098, ending exactly at EOF (42,786).
- **Fix:** replace the heuristics with tiling + checksum.

### 8. Cross-title gaps no TODO row tracks (CSB aspects)
- CSB `disk1/DungeonF.DAT` / `DungeonG.DAT` are not mentioned in the CSB doc. Both decompress and tile
  exactly (2 maps, dungeon id 12).
- CSB `disk2` files with no row: `HCSB.DAT` (word0 = 5, not DMCSB), `HCSB.HTC`, `CEDTLD`/`CEDTLS.DAT`,
  `ANIM.DAT`, and the `Portrait/`, `Sound/`, `MIDI/` folders.
- Graphics.DAT non-image items 671-748 (about 60): length-prefixed; several PCM-like (items 675, 687, 711,
  lag-1 r1 0.90-0.96); item 694 starts with "COMPAS...".
- DM1 vs CSB Graphics.DAT: 669/749 items byte-identical, 80 differ (2-5, 11, 26, 42-47, 329-378, 504,
  550, 588-650...). The CSB doc's "largely overlapping" can be quantified.
