# Dungeon Master II (Amiga): codebreaker gap audit, 2026-11-13

Report-only audit, 2026-11-13. None of these corrections have been applied yet.
Run by an independent codebreaker re-derivation: all probes were fresh Python written by the auditor
(no project code reused). The audit covered Dungeon Master, Chaos Strikes Back and DM II together;
findings that touch DM2 are repeated here so the page stands alone. Sister pages:
`docs/dungeonmaster/audit-2026-11-13.md`, `docs/chaosstrikesback/audit-2026-11-13.md`.
All offsets are file-relative. `format.md` means `docs/dungeonmaster-format.md`.

## Summary verdict

- The DM2 `IMG4` "98.9% decode" metric measures nothing, and the grammar is incomplete (wrong for about
  a third of items). Under an exact-consumption check the real structure is a 16-byte trailer plus a
  5- or 6-nibble local palette.
- The DUNGEON.DAT layer is more solid than documented (tiling, column-count oracle 725/725, checksum
  0x3D9F).
- DM2 corroborations ("map 0 level = 7 matches Sun Clan") are weaker than presented.
- Palette leads exist in shipped files (per-image trailers, PL chunks in SWSH/ENDA) that the palette TODO
  rows never looked at.
- Biggest risk: the headline decode metric is empty, so the `dm2-img8-differential` and `dm2-palette`
  rows are scoped around the wrong unknowns.

## Claims confirmed

- **DMII container** (DM2 GRAPHICS.DAT): 4,630 items, Σsize = 3,484,613 equals the payload exactly.
- **Header and section layout:** forward tiling exact for the DM2 dungeon (8/8 dungeons across the
  audit's games).
- **Map grid:** column-major, per the column-count oracle: DM2 725/725 (null control row-major:
  122/725). Confirms orientation, dimensions and the hasObject bit.
- **Map count:** 44 (per-map offset equals the cumulative byte cursor on 44/44).
- **Checksum:** 16-bit sum of all preceding bytes: DM2 0x3D9F, exact.
- The `IMG1`-family dimension words carry flags; about 751 "non-candidate" items tile exactly as images
  once the top 6 bits are masked (finding 5).

## Claims wrong or overstated

### 1. The DM2 `IMG4` "98.9% decode" metric measures nothing, and the grammar is incomplete (WRONG/OVERSTATED)
- **Docs say:** `docs/dungeonmaster-format.md:144-147`, `docs/dungeonmaster2/amiga/data-structure.md:71-74`
  ("2,237 (98.9%) decode to >=95%-filled"); gate at `tools/dungeonmaster2/amiga/export-data.ts:101-105`.
- **Why the metric is empty:** the decoder (`dungeonmaster-codec.ts:187`) loops until `pos >= w*h`, and
  its NibbleReader returns 0 past end-of-item, so nearly every item reaches 100% fill whether or not it
  parsed.
- **Audit check:** whether the run stream consumes exactly the item's bytes.
- **Evidence:**
  - Under the shipped 6-nibble grammar only 5/2,263 candidates consume exactly. 415 overrun the item;
    the rest leave leftovers.
  - The dominant leftover is exactly 32-33 nibbles: a **16-byte trailer** (one pad nibble plus 16
    bytes).
  - With "6-nibble palette + RLE + 16-byte trailer", **1,533/2,263** tile exactly.
  - The remaining 730 tile exactly with a **5-nibble** local palette + 16-byte trailer: 727/730. Only 3
    unexplained. Random residue landing on exactly 32/33 nibbles is far from chance.
  - The trailer bytes are values <=255 (782 distinct trailers, common maxima 0xEF/0xFF/0xFD), which look
    like a per-image 16-entry map from nibble to global colour index: the palette mechanism.
- **Also:** the docs contradict themselves: "26/2,263 below threshold" (1.1%) next to "the remaining
  ~11%" (`format.md:164`, `dm2 data-structure.md:89`). No discriminator found between the 5- and 6-nibble
  variants in the first palette nibble.
- **Fix:** replace the fill gate with an exact-consumption check; document the 16-byte trailer and the
  5-nibble variant as structurally confirmed; reframe `dm2-img8-differential` (the grammar is solved;
  open is the meaning of the compositing selector and variant flag); retitle `dm2-palette` (per-image
  16->256 maps, not a 16-colour table).

### 2. SWSH/TITL/ENDA `.DAT` files are tagged-chunk streams with palettes, not DMCSB containers
- **Audit found:** every such file starts with `AN` + `0140 00C8 0004` (320x200x4); tags AN, BR, P8, PL,
  SD, SF, MF, EN, SO. **PL chunks hold 16-colour palettes** as (index, r, g, b) nibbles (present in DM2
  SWSH/ENDA). Length semantics not fully resolved (quick walk stops early). DM2 files: TITL/ENDA/SWSH.DAT.
- **Fix:** add one shared "FTL AN-chunk animation" item to `dungeonmaster-format.md`.

### 3. DUNGEON.DAT field mislabelled; forward-check under-claimed
- `format.md:227` and the `mapDataOffsetWords` field name: the per-map offset is a **byte** offset
  (DM2 44/44 equals the cumulative byte cursor); `findDungeonDataOffsets` multiplies by 2
  (`dungeon.ts:335`).
- Projectile/explosion sizes are "not documented" (`dungeonmaster-dungeon.ts:140-143`,
  `format.md:255-258`), but the size table appears as data in DM2 `SKUL.FTL`+3830
  (`04 06 04 08 10 04 04 04 04 08 04 ...`) and tiles exactly at 8 and 4 bytes in MINI.DAT.
- **Fix:** rename the field, add both forward checks, add projectile = 8 / explosion = 4 to `RECORD_SIZE`.

### 4. "Visually coherent maze" and "optional 2-byte checksum" (now CONFIRMED)
- `format.md:265-274` and `:220-221`. Replace with the column-count oracle (725/725) and the byte-sum
  checksum (0x3D9F exact).

### 5. Cross-title gaps (DM2 aspects)
- DM2 GRAPHICS.DAT item 0 (80,380 B) begins with `0x8001`, likely a nested index/descriptor table.
- About 751 of DM2's "non-candidate" items tile exactly as images once the top 6 bits of the width/height
  words are masked as flags (533 six-nibble, 218 five-nibble). So `dm2-raw1-non-image-items`' ~2,367 count
  is overstated, and the dimension words carry flags.

### 6. DM2 corroborations are weaker than presented
- "Map 0 level = 7 matches Sun Clan" (`dm2 data-structure.md:31-36`, test line 19): DM2 has several maps
  per level (maps 2/3, 4/5 ... share levels), so a single level number is weak corroboration. The tiling
  and column checks are the real evidence.
- `sample_palette.IFF` is not a retail-style filename (provenance unknown). It is a 320x200 4-plane ILBM
  with a 16-entry CMAP (`000000 707070 909090 703000 ...`), and it cannot be the DM2 global palette if
  the image trailers index up to 255.
- Square type 7 is 4,320/12,192 cells and type 2 is 576. DM1 type semantics may not carry over to DM2;
  unverified.

## Unverified / open

- The 5- vs 6-nibble variant discriminator (finding 1); 3 of 730 items unexplained.
- Compositing-selector meaning (`dm2-img8-differential`).
- AN-chunk length semantics (finding 2).
- DM2 GRAPHICS.DAT item 0 structure (finding 5); DM2 square-type semantics (finding 6).

## Recommended corrections (cheapest and highest value first)

1. Replace the fill-gate at `export-data.ts:101-105` with an exact-consumption check; document the
   trailer and 5-nibble variant (finding 1).
2. Retitle `dm2-img8-differential` and `dm2-palette` (finding 1); narrow `dm2-raw1-non-image-items`
   (finding 5).
3. Fix the self-contradicting percentages at `format.md:164` / `dm2 data-structure.md:89`.
4. Rename `mapDataOffsetWords`; add projectile/explosion sizes (finding 3).
5. Downgrade the "level = 7" corroboration; cite the column-count and tiling evidence (finding 6).
6. Add rows `dm2-gfx-dimension-flags`, `dm2-gfx-item0-index`.
