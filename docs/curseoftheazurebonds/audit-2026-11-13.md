# Curse of the Azure Bonds (Amiga): gap audit, 2026-11-13

Report-only audit, 2026-11-13. None of these corrections have been applied yet. It was run by an
independent codebreaker re-derivation (own GLIB parser and method-5 decoder written from the spec,
plus read-only use of the repo decoders) over the four Gold Box Forgotten Realms titles; this page
carries the findings that touch Curse of the Azure Bonds. Sibling pages:
`docs/poolofradiance/audit-2026-11-13.md`, `docs/secretofthesilverblades/audit-2026-11-13.md`,
`docs/poolsofdarkness/audit-2026-11-13.md`.

## Summary verdict

- Containers, codecs, GEO grid and WALLDEF geometry hold up.
- The 8x8 "1bpp, 8 bytes per tile" format is wrong. Every shipped Curse wall texture
  (`walldef*-view6.png`, 180 of them) is wrong pixels, as are the walker's wall textures.
- Several status claims are stale or contradicted by the code's own output ("no compression at all",
  GEO planes "remain open").
- Palettes are not tracked anywhere; the GLIB data carries them.
- Biggest risk: the docs' visual confirmations of the 1bpp decode are circular (plausibility checks
  of a wrong decode).

## Claims confirmed

| Claim | Evidence the audit used |
|---|---|
| GLIB container | 72/72 files (family-wide): 65 stored, plus 7 compressed at the top level that decode with the audit's own method-5 decoder. |
| Method 5 | Own from-spec decoder matches the TypeScript output on 216/216 nested blocks (family-wide). Bank 202 is byte-identical between Curse (stored) and Secret (method 5), 884/884 bytes. |

## Claims wrong or overstated

### 1. WRONG: the 8x8 "1bpp, 8 bytes per tile" format (highest impact)

- **Docs say.** Header-less 1bpp MSB-first 8-byte tiles, one walldef byte = one tile:
  `curseoftheazurebonds/amiga/data-structure.md:96-117`; `goldbox-glib-format.md:336` (Render row)
  and section 5.7 (:360-390). Code: `tools/shared/goldbox-walltiles.ts:93` (`decode8x8Tiles`).
- **Audit found.** Every "TILE" sub-block is an 8-byte header followed by P bitplanes, stored
  plane-major. Header: `u16 height=8, u16 x, u16 y, u8 widthBytes=1, u8 flag`. Glyph sizes: 48 B =
  8 + 5*8, so 5 planes (Curse/Secret walls and the universal bank 203); 40 B = 4 planes (bank 202).
  The header grammar fits every glyph block: Curse 1325/1325 (and 20/20 in `8X8DA`).
- **Index mapping.** Index 0 = none, 1-45 = universal glyphs 0-44, then 46 + 70*slot + k for the
  wallset slots.
- **Evidence.**
  - Seam-continuity oracle (10 views, against a random-pair null): Curse corrected decode 0.584 vs
    null 0.201, lift 0.48; shipped 1bpp reading 0.655 vs null 0.621, lift 0.09.
  - Cross-title: 31/45 of PoR's universal glyphs share the colour partition of Curse's universal
    glyph at the same index (under the shipped reading only 1 of 122 PoR tiles matches any Curse
    glyph).
  - ASCII render with the corrected decode: Curse wall 1 is a panelled door between brick.
- **Consequences.** The "crenellation / door / herringbone" confirmations are circular. Section 5.6's
  correction ("one byte = one block, CONFIRMED") was never propagated to the code;
  `goldbox-walltiles.ts` still indexes 8-byte tiles and its module doc (~line 66) says the question
  is open.
- **Fix.** Replace `decode8x8Tiles` with a glyph decoder per grammar; rebuild the bank as
  [none, U0..U44, slot glyphs]; re-render with the seam and cross-title oracles as regression
  checks. Retire the Curse section 3a "flat bank" render: bank 202 is a 4-plane UI/arrow glyph set
  (bytes `08 1c 3e 1c...`), not wall art. Add TODO row `goldbox-glyph-format`.

### 2. Stale status contradicted by code and outputs

- **Compression.** Curse `data-structure.md:37-41` and Curse `TODO.md` (2026-08-30 block) still say
  "no compression at all"; the GLIB section 3 correction and the decoder say otherwise (7 top-level
  compressed GLIB files across the family).
- **GEO planes 0/1.** The heading at Curse `:250` still says "Planes 0/1 remain open, escalated",
  although a correction block is underneath.
- GLIB section 1 heading still says "65/72"; it should read 72/72. GLIB section 4 still mentions a
  "still-open per-wall-id tile-pixel-layout puzzle".

### 3. OVERSTATED (family-wide): ECL wallset-binding coverage

GLIB `:681-691` and `:860-869` say "every level that resolves at all resolves ALL 3 slots". The audit
verified this against level outputs for PoR (24/29, not 26/29) and Secret (15 of 51 slots set to
127); Curse levels were not singled out. Count 127/255 as unresolved, and see
`goldbox-ecl-multiwallset-slotfill` (hypothesis: loading a multi-wallset WALLDEF entry fills the
following slots too).

### 4. GEO verification numbers do not reproduce (conclusion holds)

| Check | Audit | Documented |
|---|---|---|
| Plane 3 shared-wall agreement, horizontal/vertical | 98.9/98.9 | 90.8/91.6 |
| Planes 0/1 wall-type nibbles in documented N/E/S/W order | 99.4/99.5 | not stated here |

The best wrong ordering gets at most 0.57 on the vertical axis and ties on the horizontal axis (a
N/S swap is invisible to a horizontal check). The documented "best of the other 23 permutations
55.7%" is not what a full scan gives. Replace with script-backed numbers.

## Unverified / open

- **Palettes (untracked).** GLIB "TILE" containers carry palette blocks with `height=0`: 56 B =
  8-byte header + 16 RGB888 triplets (Curse `DISKA/ALWAYS.TLB`). Found but not verified against
  screenshots (hypothesis). Add row `goldbox-glib-palette`.
- **Compressed images.** HEAD, BODY, PIC, SPRIT and BIGPIC blocks have header byte 7 = `0x02` and
  sizes that do not fit raw planes; they look like individually compressed images, the next RE
  target (`goldbox-glib-compressed-images`).
- No row for SOUNDS (`DIG8`), STRINGS (`TEXT`), `.FON`, the `SLBR`/`MXTX` music files, or ITEMS.DAT
  (2,048 B in each GLIB title, a different MD5 in each). The `*-full-catalog` rows are too broad to
  drive work.
- Not re-checked: Pools v1.3 opcode table, CFG-walk counts, plane 2 meaning.

## Recommended corrections, cheapest/highest value first

1. Glyph decoder fix and re-render (finding 1).
2. Wire the `h=0` RGB palette blocks into the GLIB output.
3. Fix the stale text (finding 2) and the GEO numbers (finding 4).
4. Count 127/255 as unresolved (finding 3).
5. Add TODO rows: `goldbox-glyph-format`, `goldbox-glib-palette`,
   `goldbox-ecl-multiwallset-slotfill`, `goldbox-glib-compressed-images`.
