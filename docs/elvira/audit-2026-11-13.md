# Elvira: Mistress of the Dark (Amiga, AGOS): codebreaker gap audit, 2026-11-13

Report-only audit, 2026-11-13. None of these corrections have been applied yet.
Run by an independent codebreaker re-derivation: an independent Python `simon_decr` (`agoslib.py`) plus
probes `t1.py`-`t10.py`, with ScummVM `engines/agos` and scummvm-tools as the reference (citation only,
master as of the audit date). The audit covered Elvira 1, Elvira II and Waxworks together; shared findings
are repeated here so the page stands alone. Sister pages: `docs/elvira2/audit-2026-11-13.md`,
`docs/waxworks/audit-2026-11-13.md`. `agos-pkd-format.md` below means `docs/agos-pkd-format.md`.

All retail files match ScummVM's detection MD5 and size exactly (`detection_tables.h:146,486-491,931-937`),
so ScummVM describes these exact files and is usable as the reference.

## Summary verdict

- Partial. The core codecs hold up, and the inline rechecks make them stronger than the docs claim (all
  628 `.pkd` files decode with the read pointer at file offset 0 and 0 bits left).
- The problems are in how the codecs were used. The Elvira 1 image count is too low: **1,654 valid
  entries, not 1,124**, and the "empty zone" statements are void.
- Several file-role descriptions are wrong (`gameamiga` is the game database, not the executable).
- The palette claims are overstated; one piece of evidence (a 0xF96 "salmon" colour) is not reproducible.
- Four TODO families (`elvira-tune-music`, `elvira-out-sfx`, `elvira-vga1-scripts`, `elvira-misc-files`)
  can be closed or almost closed cheaply, with ScummVM as the reference.

## Claims confirmed

- **`simon_decr` decode:** all 628 `.pkd` files (all three games) decode with complete bitstream
  consumption (offset 0, 0 bits left). Stronger than the doc's own "no bounds error" check. The 28 tunes,
  Waxworks `gameamiga` and `icon.pkd` pass the same check. Null control: plain files such as `text*` and
  `tables*` fail.
- **Shared container** across Elvira 1, Elvira II and Waxworks (refutes the probe recon's "different
  header").
- **Filename digit widths:** 2-digit zone ids for Elvira 1/II, 3-digit for Waxworks (`res.cpp:936-946`).
- **Image codec:** both branches. Every compressed plane decodes without overrun (6,822 images across the
  three games, 0 failures); uncompressed images fill exactly the gap to the next image (Elvira 1:
  473/473). Column-major order wins: across 6,111 compressed images vertical neighbour agreement is 0.719
  for column-major against 0.603 for row-major; 90.6% vs 69.3% of images reach at least 0.5 (quantifies the
  claim at `agos-pkd-format.md:194`).
- **Palette location and scale:** the pointer `BE16(vga1+6)` and the `*32` scale, as the engine's formula.

## Claims wrong or overstated

### 1. The picture count is truncated, and so is every "empty zone" claim (WRONG)
- **Docs say:** 5,745 images (`agos-pkd-format.md:219-221`). The table walk "stops at the first entry whose
  ... width/height is 0" (`:175-176`, `tools/shared/agos-vga.ts:180-206`). "3 zones' vga2 anim tables are
  empty" (`docs/elvira/amiga/data-structure.md:23-25`).
- **Audit found:** the early stop was copied from the debug-only dumper `dumpVgaBitmaps`
  (`debug.cpp:659-677`). The real draw path, `drawImage_init` (`vga.cpp:861-874`), looks up
  `vga2 + image*8` directly and returns on a 0x0 entry; it does not stop. The audit counted every entry
  up to the lowest non-zero data offset and walked all VC scripts in `vga1`, collecting image numbers
  passed to `vc10_draw`.
- **Evidence (Elvira 1):** early-stop walk 1,124 -> valid entries in the full table **1,654**; zones with
  pictures **65/65**. 0x0 placeholder entries sit mid-table (189 in Elvira 1). Uncompressed images fill
  the gap exactly 473/473. Of image numbers the scripts draw, 612 land on valid entries; the only
  exception is one Elvira 1 reference. Example: Elvira 1 zone 2: the old walk finds 1 image, but the
  scripts draw image 55 and the table has 55 entries.
- Across the three games the early-stop walks give 1,124 / 2,303 / 2,318 and the full tables give 1,654 /
  3,273 / 4,381 (the report puts the overall undercount at about 3,500).
- **Fix:** correct the stop rule to "skip 0x0 entries; the table ends at the lowest data offset"; re-count
  images; retract the empty-zone statements. The current section 0/3 wording ("Entry 1's offset doubles
  as the table span") also fails whenever entry 1 is a placeholder (offset 0).

### 2. Palette export gating (WRONG, affects the family; Elvira 1 not affected)
- The exporter calls `loadPalette(vga1,0,16)` for every zone (`tools/shared/agos-vga-export.ts:164`).
  Word `+2` of `vga1` holds the bank count; it equals `(BE16(+10)-BE16(+6))/32` in 321 of 321 files, zero
  deviation. 46 Waxworks zones and 3 Elvira II zones declare **0 banks** (Elvira 1 has none such), so the
  fix concerns the other two titles; see their pages. For Elvira 1 the relevant correction is finding 7.

### 3. `gameamiga` is the game database, not the AmigaOS executable (WRONG)
- **Docs say:** `docs/elvira/amiga/data-structure.md:34-36`.
- **Audit found:** ScummVM lists `gameamiga` as `GAME_BASEFILE`, read by `loadGamePcFile` /
  `allocGamePcVars` (`res.cpp:107-145,183-209`). Header carries the "runtime database" version marker
  `0x80`: Elvira 1 `36b 80 ... 2b1`. The text block's NUL-terminated string count equals the header's
  string-table count: **689/689** for Elvira 1. Strings are real game text ("A large metal banded wooden
  chest..."). The actual executable is `runit` (`000003F3` hunk header).
- **Fix:** fix the doc; add a TODO row `elvira-gamepc`: decode items, rooms, exits, subroutines via
  `readItemFromGamePc` / `readSubroutineBlock`. This is the room and exit data a walker needs; nothing
  tracks it today. Related: `start` is `GAME_RESTFILE`, `icon.dat`/`icon.pkd` is `GAME_ICONFILE`,
  `stripped.txt` is the TEXT index (9-byte entries for Elvira 1), `tbllist`/`xtbllist` index
  `tables*`/`xtable*`.

### 4. The `*tune` files are simon_decr-compressed ProTracker modules (TODO rows can close)
- **Docs say:** "un-probed; likely tracker-module ... not .pkd" (`agos-pkd-format.md:251-254`); row
  `elvira-tune-music`.
- **Audit found:** all 28 tune files (all games) decompress with full consumption and contain `M.K.` at
  offset 1080. File size equals `1084 + patterns*1024 + sample bytes` exactly in 24 of 28 (the four
  exceptions are Waxworks sub-tune files). Song names present (e.g. "elvira loader", "catacombs").
- **Fix:** mark the format solved; keep a small extractor task.

### 5. `.out` sound files follow ScummVM's per-game raw layouts (TODO rows can close)
- **Docs say:** "undecoded ... probably-uncompressed" (`agos-pkd-format.md:239-246`); row `elvira-out-sfx`.
- **Audit found:** per `loadVGASoundFile`/`loadSound` (`res_snd.cpp:719-756,894-957`) there is no
  compression; samples are signed 8-bit PCM at 8000 Hz by default (`playRawData`, `sound.cpp:613-622`).
  **Elvira 1:** 12-byte big-endian records `[u16 0][u16 size][u16 0][u16 id][u32 offset]`. All 19 Elvira 1
  files tile exactly to end-of-file (19/19).
- **Fix:** mark solved.

### 6. The palette claims are overstated; one piece of evidence is not reproducible (OVERSTATED / WRONG)
- **Docs say:** bank 0 is the only bank that matters (`agos-pkd-format.md:151-154`,
  `docs/elvira/amiga/data-structure.md:41-42`); evidence `setPaletteSlot` (`:126-138`); a 0xF96 "salmon"
  colour in Elvira 1 zone 64's second bank (`:140-149`).
- **Audit found:** the main palette load is `vc22_setPalette` (`vga.cpp:1152-1235`), never mentioned. For
  **Elvira 1** with an argument below 1000 it loads only **13** colours from the zone; colours 13-31 come
  from a hard-coded `extraColors` table. The zones' own colours 13-15 disagree with that table (most
  often `500/332/777`, 17 of 65 zones, against the engine's `500/332/665`; slot 13 varies `700`, `711`,
  `600`). Icons drawn below y=133 get `paletteMod=16` (`gfx.cpp:971-973`). Scripts select banks other than
  0 often: Elvira 1 `vc22` arguments 1-16 appear 168 times against 229 for bank 0. Palette nibbles are
  0-7 (3-bit) in every Elvira 1 palette, including zone 64's four banks, so no 0xF96 colour exists there.
  At nibble 7, `*32` gives 224 and `*17` gives 119, so "both are close" is false.
- **Verdict:** the `*32` scale is correct per source; calling the per-zone bank-0 palette "CONFIRMED" for
  rendering is overstated.
- **Fix:** remove the 0xF96 paragraph; relabel as "per-zone bank 0, rendered (unverified against
  scripts)"; upgrade `elvira-palette-slots` from deferred to open, noting the 13-colour/`extraColors` and
  `paletteMod` rules.

### 7. The `*-vga1-scripts` rows are mis-scoped
- **Docs say:** vga1 holds "object definitions, room text, VC opcode scripts" (`agos-pkd-format.md:247-250`).
- **Audit found:** object definitions and room text are in `gameamiga` (finding 3). `vga1` holds the
  palette banks, then the image and animation tables (header at `BE16(+10)+20`, `vga.h:85-95`), then VC
  scripts. Walking scripts with ScummVM's parameter-length tables (`vga.cpp:310-330`) gives 815 scripts
  (Elvira 1), 0 bad opcodes. The id/100 = zone rule holds for 5,831 of 5,835 table entries (all games).
- **Fix:** rescope the rows to "VC script semantics"; the structure is already walkable.

### 8. Decompressor table and decode claims (doc wrong, code fine)
- In `agos-pkd-format.md:63-70`, the match rows claim 8 extra length bits and base 12. Per
  `extract_agos.cpp:104-136`, matches `1,00` and `1,01` have fixed length (2, 3) and no extra bits, and
  `1,10` reads its length as 8 bits with 12 offset bits. The code (`agos-vga.ts:85-118`) is correct.
- "Uncompressed" is not rare (`:200-201`): 473/1,654 in Elvira 1 (29%).

### 9. Inventory errors and cross-title inconsistencies (Elvira 1 aspects)
- **Zone ids:** 1-3, 6-9 and 17-74, not "contiguous 6-74" (`docs/elvira/amiga/data-structure.md:19-20`);
  zones 10-16 are missing.
- File counts: "130 `.pkd`/`.out` files" is actually 130 `.pkd` plus 19 `.out` (this figure is cited in
  the Elvira doc); "84 screen samples" (`agos-pkd-format.md:222`) is actually 124 on disk.
- Stale comments in `agos-vga.ts`: line 6 points at `data/_unexplored_/...`; lines 26-31 cite a
  non-existent Elvira II "Container format" section; lines 146-149 put the swatch comparison in the Elvira
  1 doc, when it is in `docs/agos-pkd-format.md` section 2.
- `Pics/` provenance: the 4 `Pics/` ILBMs carry a "SKID ROW" credit and are not in ScummVM's file list,
  so they are release-group add-ons, not retail data; same for `tmp.txt` ("Chip - 449360").

## Process notes

- The "no bounds error" decode verification in `agos-pkd-format.md:41-48` is weak; the audit's
  consumption-to-offset-0 check is the stronger one.
- Tracker prose is not evidence: "visually verified" and count claims were re-derived from bytes, which
  exposed the truncated count and the unreproducible 0xF96 anecdote.
- Candidate lesson: a reference project's debug dumper loop (`break` on the first 0x0 entry) silently
  truncates sparse tables; port the runtime lookup (index plus skip) instead.

  repo); no files in the repo changed.
